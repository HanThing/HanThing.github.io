# HanThing 지식 운영 기준

이 위키는 Karpathy의 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)를 학습 기록에 맞게 적용한다. 그래프는 결과의 한 표현이다. 핵심은 출처에서 지식을 종합하고, 기존 설명을 갱신하며, 근거를 찾아 답하는 과정이다.

## 원본과 기준

- `content/`의 공개 Markdown이 게시된 지식의 기준이다. 웹 화면과 `INDEX.md`, `content-data.js`는 여기서 생성한다. 본문을 두 벌 관리하지 않는다.
- 원문 학습 대화·노트북·강의 자료는 수정하지 않는다. 공개 글에는 필요한 사실만 재구성하고 공개 가능한 출처 또는 식별 가능한 자료명을 남긴다. 사적인 주소·전체 대화·원본 PDF는 이 디렉터리에 넣지 않는다.
- Notion은 게시 전 임시 수집함이다. 게시 후 사이트와 양방향 동기화하지 않는다. 출처의 증거는 유지하되, Notion 관리 체계나 자동 수집 작업은 만들지 않는다.
- `INDEX.md`는 내용별 탐색, `CHANGELOG.md`는 변경 이력이다. 이력을 과거 학습 완료의 증거로 사용하지 않는다.

## Ingest — 새 학습 기록 반영

1. 요청한 세션·자료 범위를 확인하고 `INDEX.md`에서 기존 관련 노트를 찾아 읽는다.
2. 실제 질문, 당시 생각, 실제 시도, 관찰한 결과, 제공받은 설명, 남은 의문을 구분한다. 확인되지 않은 시도·이해·프로젝트·과제 질문을 만들어 채우지 않는다.
3. 날짜별 기록(`type: journal`)은 당시 맥락을 남긴다. 개념(`concept`)은 기존 설명을 우선 갱신한다. 새 근거와 충돌하면 두 주장과 출처·확인 필요 사항을 함께 표시한다. 모순을 말없이 덮어쓰지 않는다.
4. 의미 있는 실제 질문은 `## 질문: 제목`, 새로 만든 복습 문제는 `## 퀴즈: 제목`으로 구분한다. 퀴즈 정답·해설은 접을 수 있게 하고 응답하지 않은 문제를 맞혔다고 기록하지 않는다. 각 목록은 본문 제목에 연결하므로 복사본을 만들지 않는다.
5. `weekly`는 확인한 공식 과제 질문에 직접 답하는 글, `project`는 실제 진행한 프로젝트 기록이다. 없는 과제를 추측하거나 빈 프로젝트를 꾸미지 않는다.
6. 관련 노트를 양방향으로 필요한 만큼 연결하고 `CHANGELOG.md`에 날짜·출처·변경한 노트·남은 검증을 추가한다. `node generate-catalog.mjs`로 색인과 홈 데이터를 갱신한다.
7. 아래 lint 후 요청된 게시 범위만 반영한다. 정리 요청 자체를 항상 공개 게시 승인으로 해석하지 않는다.

## Query — 이 지식으로 답하기

`INDEX.md`에서 후보를 찾고 관련 Markdown의 해당 절·출처를 읽는다. 답에는 근거 노트를 연결하며, 사용자의 질문 기록과 일반 설명을 구분한다. 기록에 없는 사실은 없다고 말한다. 최신성이 필요한 주장은 원 출처를 다시 확인한다. 유용한 새 종합은 사용자가 저장을 요청한 경우 기록·관련 개념·이력에 함께 반영한다.

## Lint — 게시 전과 점검 요청 시

- 자동: `node generate-catalog.mjs --check`, 색인 재생성, 빌드 후 링크/공개 범위 검사. 새 지식 문서에는 `title`, `date`, `type`, `publish: true`, `tags`, `sources`가 필요하다. `published`는 학습일과 정리·게시일이 다를 때 사용한다.
- 내용: 관련 노트 간 모순·중복, 오래된 주장, 출처가 모호한 문장, 연결이 없는 문서, 개념이 필요한 미해결 질문을 확인한다. 링크 검사 통과를 의미 검증 통과로 부르지 않는다.
- 출처 부족은 누락으로 기록한다. 기존 Python 이관 자료처럼 원문 전체를 이번에 재검증하지 않은 자료는 재검증했다고 쓰지 않는다.
- 오류는 원본 Markdown에서 수정한다. 수정한 노트·이유·영향·확인 결과를 이력에 추가한다. 스케줄러나 자동 LLM 실행은 없다.

## 사람에게 보이는 화면

최근 기록, 질문, 퀴즈, 주제·글 종류로 찾는 목록을 우선한다. 운영 파일·태그 인덱스·일정표는 지식 별 수에 넣지 않는다. 별은 실제 지식 문서 수를 나타내며 숙련도를 나타내지 않는다. 출처와 운영 파일은 공개 가능하지만 화면에서 숨기는 것만으로 비공개라고 여기지 않는다.
