Colab 수업에서 모듈과 패키지를 배우던 날이었다. 설명에 `calculator.py`라는 단일 파일과 `calculator/`라는 패키지 폴더가 번갈아 등장하면서 “가져온다”는 말의 뜻이 흐려졌다. 아래 질문들은 파일이 저장된 위치와 실행 중 접근할 수 있는 이름을 구분하는 과정이다.

여기서 패키지 예는 다음 **한 구조**를 기준으로 읽는다. 실제 개인 파일의 경로가 아니라 당시 설명을 위한 예다.

```text
예제 프로젝트/
├── main.py
└── calculator/
    ├── __init__.py
    ├── basic.py
    └── advanced.py
```

질문 제목은 실제 발언의 뜻을 유지해 다듬었다. **의도**는 사용자가 직접 밝힌 경우를 제외하면 대화 맥락을 바탕으로 정리한 해석이다.

## 질문: 모듈은 .py 하나일까, 여러 파일을 묶은 것일까?

**상황:** 수업의 모듈 설명을 보고 파이썬 파일 하나를 뜻하는지, 여러 파일을 모은 것을 뜻하는지 물었다.

**의도:** 이후 `import` 예제를 읽을 때 파일·폴더·기능의 단위를 정확히 잡으려 했다.

**핵심 답변:** 입문 예에서는 `.py` 하나를 모듈, 모듈들을 묶은 구조를 패키지로 구분한다. 다만 패키지도 모듈의 한 종류이고 내장 모듈처럼 `.py` 파일이 아닌 모듈도 있으므로, 단순한 파일 개수 공식이 전부는 아니다.

이 기록의 `basic.py`는 모듈이고 `calculator/`는 일반적인 패키지다. 이름이 비슷한 별도 예 `calculator.py`와 혼용하지 않는다.

## 질문: 지금 쓰는 .ipynb도 모듈로 import할 수 있을까?

**상황:** Colab에서 공부 중이어서, 파이썬 코드가 들어 있는 노트북 파일도 같은 모듈인지 물었다.

**의도:** `.py` 예제와 자신이 실제 작성하는 노트북의 관계를 이해하려 했다.

**핵심 답변:** `.ipynb`는 코드·설명·출력 등을 함께 담은 노트북 형식이다. 보통의 `import`가 `.py`처럼 직접 읽는 형식은 아니다. 재사용할 코드를 `.py`로 분리하면 노트북에서 가져다 쓸 수 있다.

별도 도구로 노트북을 불러오는 방법과 기본 문법은 구분한다. 이날 질문이 그 도구를 설치하거나 성공적으로 실행했다는 뜻은 아니다.

## 질문: print와 input은 왜 import하지 않아도 쓸 수 있을까?

**상황:** 함수를 쓰려면 정의된 모듈을 가져와야 한다는 설명과, 항상 바로 사용하던 `print()`·`input()`이 맞지 않는다고 느꼈다.

**의도:** 함수가 정의된 위치와 이름을 바로 사용할 수 있는 조건을 연결하려 했다.

**핵심 답변:** `print`와 `input`은 내장 이름으로 제공돼 파이썬이 이름을 찾을 때 자동으로 확인한다. 모든 모듈의 모든 함수가 자동으로 제공되는 것은 아니다.

이는 [[learning/2026-09-18-notebook-state|list라는 이름으로 내장 기능을 가린 오류]]와도 연결된다. 내장 이름은 사용할 수 있지만 같은 이름을 새 값에 붙여 가릴 수 있다.

## 질문: 패키지를 import했는데 그 안의 basic도 가져온 것 아닐까?

**상황:** `from calculator import basic` 대신 `import calculator`만 하면 되는지 질문했다. 이어 폴더 안에 `basic.py`가 있으니 `calculator.basic`으로 접근할 수 있어야 하는 것 아닌지 여러 차례 확인했다.

**의도:** 패키지를 가져온다는 말이 폴더 안 모든 파일을 한꺼번에 사용할 수 있게 한다는 뜻인지 알고 싶었다.

**핵심 답변:** 디스크에 파일이 존재하는 것과 실행 중 모듈이 로드된 것은 다르다. `__init__.py`가 비어 있고 `basic`을 아직 불러오지 않은 새 환경이라면, `import calculator`만으로 `calculator.basic`이 생기지는 않는다.

| 코드 | 예제에서 하는 일 |
| --- | --- |
| `import calculator` | 패키지 준비 및 이름 연결 |
| `import calculator.basic` | 하위 모듈도 불러와 `calculator.basic`으로 접근 |
| `from calculator import basic` | 필요한 모듈을 불러와 현재 코드에서 `basic`으로 접근 |

설명 도중에는 `__init__.py`에 `from . import basic`이 있는 경우와 없는 경우가 섞여 있었다. **그 조건 차이를 빠뜨린 설명도 혼동의 원인이었다.** 사용자가 폴더 구조를 몰랐다고만 요약하면 질문 의도를 놓친다.

## 질문: __init__.py는 정확히 무엇이고 초기화는 무엇을 할까?

**상황:** 패키지 설명에서 계속 등장하는 `__init__.py`의 이름과 역할을 물었다.

**의도:** 낯선 파일 이름의 뜻부터 패키지를 사용할 때 맡는 역할까지 구체적으로 이해하려 했다.

**핵심 답변:** 여기서는 일반 패키지를 처음 불러올 때 실행되는 파이썬 파일이다. 필요한 초기 준비를 적으며 비워 둘 수도 있다. 초기화가 삭제를 뜻하지는 않는다.

예를 들어 파일에 `version = "1.0"`을 적으면 패키지의 이름 공간에 `version`이 생긴다. `from . import basic`을 적었다면 그 준비 과정에서 `basic`도 불러온다. 모든 패키지 형태에 이 파일이 반드시 있다는 규칙으로 일반화하지는 않는다.

## 질문: import하면 파일이 내 위치로 오는 걸까? init은 어디서 실행될까?

**상황:** 사용자는 패키지가 자신의 위치로 “온다”고 이해해 혼동된다며 더 정확한 용어를 요청했다.

**의도:** 파일 이동·현재 폴더·코드 실행 위치가 같은 말처럼 쓰이는 문제를 풀려 했다.

**핵심 답변:** `import`는 파일을 복사하거나 현재 작업 폴더를 바꾸는 명령이 아니다. 실행 중인 파이썬이 패키지 코드를 처리하고, 그 패키지의 이름 공간을 현재 코드에서 접근할 수 있게 연결한다.

```python
# calculator/__init__.py 안의 예제 코드
version = "1.0"
```

```python
# 사용하는 쪽의 예제 코드
import calculator
print(calculator.version)
```

`version`이 현재 코드의 일반 변수로 자동 복사된 것이 아니므로 `calculator.version`으로 접근한다. **파일 경로**, 상대 경로의 기준인 **작업 디렉터리**, 이름을 관리하는 **이름 공간**을 나눠 생각해야 했다.

## 질문: # calculator/__init__.py는 주석인데, 실제 코드는 어디에 적을까?

**상황:** 설명 코드의 `# calculator/__init__.py`가 주석인지 확인했고, 이어 Colab에서 실제 파일을 어디에 작성·저장하는지 물었다. 셀에 쓰는 예와 파일 편집기로 쓰는 예의 경계가 불분명했다.

**의도:** 설명용 파일명 표시를 실제 파일 생성 동작으로 오해하지 않고 수업의 작성 방식을 따르려 했다.

**핵심 답변:** `#`부터 줄 끝까지는 실행되지 않는 주석이다. 파일 위치를 설명한 줄을 복사해도 파일이 생기지 않는다. 그 경로에 실제 `.py` 파일을 만들어 코드를 저장하는 작업은 별도로 필요하다.

`version = "1.0"`은 다음 줄의 실행 코드다. 노트북 셀의 코드를 저장하는 것과 별도의 `calculator.py` 파일을 만드는 것도 구분한다. 이 기록은 특정 Colab 메뉴의 현재 위치나 파일 저장 완료를 주장하지 않는다.

## 질문: 명령어 말고 수업처럼 파일을 만들고 열어서 붙여넣으려면?

**상황:** 사용자는 `calculator.py`를 어디에 작성하고 저장하는지 반복해 물었다. 답변은 계속 `%%writefile`을 제시했지만, 사용자가 원한 것은 수업에서 본 파일 목록의 새 파일 생성·편집 방식이었다.

**의도:** 파일을 만드는 결과만이 아니라 자신이 본 작업 방식과 저장 위치를 연결하려 했다. 사용자는 “파일을 만든 후에 그걸 열어가지고 거기다가 복사 붙여넣기”하고 싶다고 명시했다.

**핵심 답변:** 노트북 셀의 `%%writefile`은 셀 내용을 별도 파일로 저장하는 방식이고, 파일 목록에서 생성한 `.py`를 편집하는 방식은 그 파일에 직접 코드를 적는 방식이다. 후자의 파일 본문에는 `%%writefile` 줄을 넣지 않는다.

당시 답변은 요청을 잘못 이해했음을 정정하고 새 파일 메뉴를 확인해 안내했다. Colab 실행 환경에 만든 파일과 노트북 자체·개인 컴퓨터·Drive 저장은 별개라는 점도 설명했다. 이 문서에서 현재 UI 메뉴나 지속 보관 여부를 새로 검증한 것은 아니다.

## 질문: __init__.py는 main이 실행할까, import문이 실행할까?

**상황:** 클래스 초기화와 비교하던 중, 패키지 초기화 파일을 “누가, 어느 순간” 실행하는지 다시 물었다.

**의도:** 파일 이름과 실행 주체, 실행을 시작하는 계기를 구분하려 했다.

**핵심 답변:** 실제 실행 주체는 파이썬 인터프리터이고, `import`가 계기다. 처음 패키지를 준비할 때 초기화 코드를 실행한 뒤 `import` 다음 줄로 돌아온다. `main.py`라는 파일 이름 자체에 초기화를 맡기는 특별한 역할이 있는 것은 아니다.

설명한 순서는 `import 전 출력 → 패키지 초기화 출력 → import 후 출력`이었다. 같은 실행 환경에서 다시 `import`하면 보통 이미 로드한 모듈을 재사용하므로 초기화 파일을 매번 다시 실행하지 않는다.

## 질문: 제작자가 init에 모듈을 미리 정하면 사용하는 쪽은 어떻게 선택할까?

**상황:** 사용자는 “`__init__.py`가 어떤 모듈을 연결할지 선택한다”는 설명에 모순을 지적했다. 파일 내용은 제작자가 이미 정했는데 호출하는 사람이 원하는 모듈을 고른다는 설명과 어떻게 함께 성립하는지 물었다.

**의도:** 패키지의 기본 준비와 사용자의 구체적인 `import` 요청이 충돌하는지 확인하려 했다.

**핵심 답변:** `__init__.py`는 허용할 모듈을 선택하는 함수나 허용 목록이 아니다. 제작자가 적은 초기화 코드와 사용자가 요청한 하위 모듈 로딩은 각각 진행할 수 있다.

```text
제작자: __init__.py에 from . import basic 작성
사용자: from calculator import advanced 실행
새 환경: 패키지 초기화로 basic 준비 → 요청한 advanced도 로드
```

당시 답변은 앞선 “선택하는 함수”라는 설명이 부정확했음을 인정하고 바로잡았다. 사용자는 이어 “이해했다”고 말한 뒤 `self` 질문으로 넘어갔다. 패키지 예제를 직접 실행해 확인한 기록과는 구분한다.
