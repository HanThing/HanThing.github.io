수업의 파일 읽기·쓰기 설명을 더 자세히 요청한 뒤, 설명 속 단어장 코드를 한 줄씩 되물었다. 막힌 곳은 단순한 메서드 이름이 아니라 **파일 → 열린 파일 객체 → 읽어온 문자열 → 나눈 값**의 연결이었다.

아래는 당시 설명용 단어장 예제를 상대 파일명으로 재구성한 것이다. 실제 사용자가 작성·실행해 성공한 코드라는 뜻은 아니다. `vocabulary.txt`에 `apple: 사과`와 `banana: 바나나`가 한 줄씩 있다는 조건이다.

```python
with open("vocabulary.txt", "r", encoding="utf-8") as f:
    for line in f:
        line = line.strip()
        eng, kor = line.split(": ", 1)
        print(eng, kor)
```

질문 제목은 실제 발언의 뜻을 유지해 다듬었다. **의도**는 사용자가 직접 밝힌 경우를 제외하면 대화 맥락을 바탕으로 정리한 해석이다.

## 질문: split은 구분자를 여러 개 지정할 수 있을까? re는 무엇일까?

**상황:** 파일 읽기 설명에 앞서 문자열을 여러 구분자로 나누는 방법을 물었고, 답변의 `re.split`을 보고 `re`가 무엇인지 되물었다.

**의도:** 쉼표·세미콜론·공백 중 어느 하나에서 나누는 규칙을 표현하려 했다.

**핵심 답변:** 문자열의 `split(",;")`는 `,;`라는 연속 문자열을 구분자로 본다. 여러 종류 중 하나를 쓰려면 정규 표현식을 다루는 표준 모듈 `re`의 `split` 등을 사용할 수 있다. 공백류만 나누려면 인자 없는 `text.split()`으로 충분하다.

당시 제시된 설명용 예다.

```python
import re
re.split(r"[,;\s]+", "사과,바나나;포도 딸기")
# ['사과', '바나나', '포도', '딸기']
```

`[,;\s]+`는 쉼표·세미콜론·공백류가 이어진 구간을 구분자로 삼는다.

## 질문: strip에 쉼표를 넣었는데 가운데 쉼표는 왜 남을까?

**상황:** 여러 제거 문자를 지정하는 설명에서 `",사과,바나나;".strip(",;")`의 결과를 보고 중간 쉼표가 남는 이유를 물었다.

**의도:** 지정한 문자를 문자열 전체에서 지우는 기능인지, 끝에서만 처리하는 기능인지 확인하려 했다.

**핵심 답변:** `strip`은 양 끝에서 지정된 문자들을 제거한다. 왼쪽은 `사`를 만나면, 오른쪽은 `나`를 만나면 멈추므로 내부 쉼표는 남는다. 결과는 `"사과,바나나"`다.

`strip(",;")`는 두 글자짜리 구분자로 나누는 `split(",;")`과 다르게, 쉼표와 세미콜론 각각을 제거 대상으로 본다. 위치와 무관하게 모든 쉼표를 없애는 작업은 `replace` 같은 별도의 변환이다.

## 질문: with A as B는 무슨 뜻이고 f는 파일 경로를 담은 포인터일까?

**상황:** 사용자는 `with A as B`를 말로 어떻게 이해할지, `f`가 정확히 무엇인지 함께 물었다. 파일 위치를 가리키는 포인터처럼 생각해도 되는지도 확인했다.

**의도:** 문법의 이름보다 각 값의 실체를 알고 싶었다. 특히 경로 문자열과 파일 객체를 구분하려는 질문이었다.

**핵심 답변:** 이 예에서 `open`은 열린 파일을 다루는 객체를 반환하고 `f`는 그 객체를 참조하는 이름이다. `with` 구역에서 이를 사용하고, 구역을 벗어나면 파일을 닫도록 정리한다. `f`는 파일 경로 문자열 자체가 아니다.

```text
"vocabulary.txt" → 위치를 나타내는 문자열
open(...)       → 열린 파일 객체
f               → 그 객체를 참조하는 이름
f.read()        → 객체에 읽기 동작 요청
```

`f` 대신 `vocab_file`이라는 이름을 써도 된다. 모든 `with`가 파일을 다루는 것은 아니며, 파일 예에서 종료 정리가 닫기에 해당한다.

## 질문: 파일에 쓰기 권한이 없는데 w로 열면 어떻게 될까?

**상황:** 사용자는 파일의 접근 권한과 `open`에 전달하는 읽기·쓰기 모드가 어떤 관계인지 물었다.

**의도:** 코드에서 쓰기 모드를 정하는 것만으로 실제 파일을 수정할 수 있게 되는지 확인하려 했다.

**핵심 답변:** 운영체제가 허용한 접근 권한과 이번 파일 객체의 열기 모드는 별개다. `"w"`가 권한을 새로 주지는 않는다. 쓰기 권한이 없으면 열기가 실패할 수 있고, 권한이 있어도 `"r"`로 연 객체로는 쓸 수 없다.

당시 모드 설명에서는 `"w"`가 기존 파일을 여는 순간 내용을 비운다는 점도 구분했다. 이 질문은 실제 권한 오류를 겪었다는 기록이 아니라 조건을 가정한 질문이다.

## 질문: close하지 않으면 실행이 파일에 머물러 다음 코드에 영향을 줄까?

**상황:** 사용자는 닫지 않으면 파일을 편집하는 상태에 실행이 머물러 이후 코드에 영향을 주는 것인지 자신의 이해를 확인했다.

**의도:** 파일을 닫아야 하는 이유가 실행 순서 때문인지 자원 관리 때문인지 구분하려 했다.

**핵심 답변:** 파일이 열려 있어도 다음 코드는 계속 실행된다. 닫는 이유는 열린 자원을 정리하고 남아 있는 쓰기 버퍼를 전달하기 위해서다. 파일이 열려 있다는 상태와 실행 흐름이 그곳에 갇혀 있다는 설명은 다르다.

`with`는 파일 사용 구간이 끝났을 때 닫는 일을 빠뜨리지 않도록 한다. 설명이 제공됐지만 파일을 일부러 열어 두고 결과를 비교한 사용자 실험 기록은 없다.

## 질문: read가 반환하는 것은 문자열일까, 객체일까?

**상황:** 열린 파일 객체 설명 뒤 `read()`가 반환하는 값의 종류를 물었고, 객체라는 용어 자체도 다시 확인했다.

**의도:** `f`와 파일 내용이 같은 것인지, 문자열과 객체가 서로 다른 분류인지 알고 싶었다.

**핵심 답변:** 텍스트 모드의 `read()`는 문자열 객체를 반환한다. 따라서 “문자열인가, 객체인가”는 양자택일이 아니다. `f`는 파일 객체이고 읽은 내용은 별도의 문자열이다. 바이너리 모드에서는 바이트 객체를 반환한다.

```python
with open("vocabulary.txt", "r", encoding="utf-8") as f:
    text = f.read()
# 여기서는 파일이 닫혔어도 text는 이미 읽은 문자열로 남는다.
```

객체의 뜻을 더 물은 과정은 [[learning/2026-09-18-objects-and-self|객체·인스턴스·self 기록]]에서 이어진다.

## 질문: readline의 한 줄은 무엇이며 어디까지 읽었는지 누가 기억할까?

**상황:** `readline()`의 “한 줄”이 무엇으로 정해지는지, 다음 호출이 어떻게 이어지는 곳에서 읽는지 물었다.

**의도:** 화면에서 보이는 줄과 파일의 줄바꿈, 파일 내용과 읽기 상태를 구분하려 했다.

**핵심 답변:** 텍스트 파일에서 한 줄은 줄바꿈이나 파일 끝으로 구분된다. 화면 너비 때문에 꺾여 보이는 줄과는 다르다. 열린 파일 객체와 입출력 시스템이 현재 읽기 위치를 관리하므로 다음 읽기는 이어지는 위치에서 시작한다.

예제의 첫 읽기는 `"apple: 사과\n"`, 다음 읽기는 `"banana: 바나나\n"`를 반환한다. 끝까지 읽은 뒤에는 남은 내용이 없으며, 파일 내용이 삭제된 것은 아니다. 처음으로 돌아가려면 다시 열거나 열린 객체에서 `seek(0)`을 사용할 수 있다.

## 질문: for line in f의 line은 정해진 이름일까?

**상황:** 한 줄씩 읽는 코드에서 `line`을 임의로 지어도 되는지 물었다.

**의도:** 한 줄씩 읽히는 이유가 변수 이름 때문인지 파일 객체의 동작 때문인지 구분하려 했다.

**핵심 답변:** `line`은 작성자가 정한 변수 이름이다. `for row in f`로 바꿔도 파일 객체는 다음 줄을 제공한다. 읽은 문자열을 이후 코드에서도 같은 이름으로 사용하면 된다.

이는 [[learning/2026-09-18-lambda-map-sort|sort의 고정 매개변수 key와 람다의 x를 구분한 질문]]과 닿아 있다. 어떤 이름은 API가 정했고 어떤 이름은 지금 코드를 쓰는 사람이 정한다.

## 질문: line.split(": ", 1)에서 막혀 뒤 코드를 이해할 수 없어요

**상황:** 단어장 예제의 `eng, kor = line.split(": ", 1)`을 보고, 특히 오른쪽 호출이 이해되지 않아 다음 줄로 넘어갈 수 없다고 말했다.

**의도:** 한 줄 문자열이 두 변수로 바뀌는 중간 결과를 먼저 확인하려 했다.

**핵심 답변:** `": "`는 콜론과 공백을 합친 구분자이고 `1`은 최대 분할 횟수다. 첫 번째 값을 선택하는 인덱스가 아니다. `"apple: 사과"`를 한 번 나누면 `['apple', '사과']`가 된다.

```text
읽은 한 줄          "apple: 사과\n"
strip 뒤            "apple: 사과"
split(": ", 1) 뒤  ["apple", "사과"]
언패킹 뒤           eng = "apple", kor = "사과"
```

`"apple: 사과: 과일"`이라면 두 번째 조각은 `"사과: 과일"`로 남는다. 이 예제는 각 줄에 구분자가 있다는 조건이며, 구분자 없는 줄까지 항상 두 변수로 나눌 수 있는 코드는 아니다.

## 질문: 오른쪽이 두 값을 가진 튜플이어도 eng, kor로 받을 수 있을까?

**상황:** `split`의 리스트 결과를 두 변수로 받는 설명 뒤, 오른쪽이 튜플이어도 같은 문법을 쓸 수 있는지 물었다.

**의도:** 방금 본 문법이 `split`에만 붙는 특별한 기능인지 더 일반적인 값 배정인지 알고 싶었다.

**핵심 답변:** `eng, kor = ("apple", "사과")`도 가능하다. 순회 가능한 값들을 왼쪽 변수에 나누어 배정하는 언패킹이다. 이 두 변수 형태에서는 오른쪽도 정확히 두 값이어야 한다.

관련 개념: [[python/files-and-with|파일과 with]], [[python/iterables-and-iterators|반복 가능한 객체]], [[python/args-and-kwargs|인자 전달과 풀어 쓰기]]. 마지막 링크의 함수 인자 언패킹은 관련 개념이며, 이날 `args`·`kwargs`를 별도로 질문했다는 뜻은 아니다.

위 질문들은 설명을 요청·확인한 기록이다. 단어장 코드를 수정하거나 실행해 성공했다는 후속 기록은 확인하지 않았다.
