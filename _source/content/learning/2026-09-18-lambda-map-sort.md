이날 두 문제를 비교했다. 17번은 숫자 `[1, 2, 3, 4, 5]`를 제곱한 새 리스트를 만들고, 15번은 `['apple', 'kiwi', 'banana', 'cherry']`의 원래 단어들을 길이순으로 정렬하는 문제였다. 정답 코드를 읽어도 **요소 하나가 어디에서 함수로 전달되는지** 연결되지 않아 질문이 이어졌다.

질문 제목은 실제 발언의 뜻을 유지해 다듬었다. **의도**는 사용자가 직접 밝힌 경우를 제외하면 대화 맥락을 바탕으로 정리한 해석이다.

## 질문: lambda는 무엇이고 왜 쓰는 걸까?

**상황:** `squares = list(map(lambda x: x**2, nums))`를 문법 요소별로 설명받은 뒤, “람다의 본질”과 사용하는 이유를 다시 물었다.

**의도:** 코드 한 줄을 외우기보다, `lambda`가 어떤 기능을 대신하는지 이해하려는 질문이었다.

**핵심 답변:** `lambda x: x**2`는 값 하나를 받아 제곱한 결과를 반환하는 함수다. 리스트를 순회하는 기능은 없다. 짧은 식으로 표현할 함수를 다른 함수에 바로 전달할 때 쓴다.

당시 설명의 두 표현은 같은 계산을 한다.

```python
def square(x):
    return x ** 2

# 함수 이름 없이 같은 계산을 표현
lambda x: x ** 2
```

사용자는 “필요한 것만 남겨 짧게 쓴 문법”으로 다시 말했고, 설명에서는 **식 하나라는 제한**을 덧붙였다. 모든 `def` 함수를 기계적으로 줄일 수 있다는 뜻은 아니다.

## 질문: map은 결국 함수를 호출하기 위해 있는 걸까?

**상황:** `lambda` 설명 뒤 `map`의 역할을 물었고, “결국 함수 호출의 역할을 위해 map이 있는 거네?”라고 확인했다.

**의도:** 함수를 만드는 역할과 여러 값에 적용하는 역할을 분리하려 했다.

**핵심 답변:** 함수 한 번은 `square(3)`으로도 호출한다. `map(square, nums)`는 여러 입력에 같은 함수를 적용하는 반복을 맡는다. 결과는 필요할 때 꺼내는 이터레이터이며, `list(...)`가 결과를 소비해 새 리스트를 만든다.

```python
nums = [1, 2, 3, 4, 5]
squares = list(map(lambda x: x ** 2, nums))
# 설명한 결과: [1, 4, 9, 16, 25]
```

요청한 추가 사례에서는 `list(map(int, ["10", "20"]))`도 다뤘다. 이미 있는 함수 `int`를 전달할 수 있으므로 `map`과 `lambda`가 반드시 함께 쓰이는 것은 아니다.

## 질문: map을 쓰지 않았는데 sort가 각 단어에 함수를 적용하는 이유는?

**상황:** 15번의 `words.sort(key=lambda x: len(x))`를 보고, 앞선 제곱 문제처럼 `map`으로 요소를 전달하지 않았는데 왜 가능한지 물었다.

**의도:** 람다가 단어 하나를 받는 순간과 그 호출을 담당하는 코드를 찾으려 했다.

**핵심 답변:** 이 경우에는 `sort`가 각 단어에 기준 함수를 적용한다. `map`은 반환값을 새 결과로 제공하고, `sort`는 반환값을 비교 기준으로 삼아 원래 요소의 순서를 바꾼다.

| 코드 | 요소를 함수에 전달하는 쪽 | 결과의 쓰임 |
| --- | --- | --- |
| `list(map(len, words))` | `map` | 길이들을 담은 새 리스트 |
| `words.sort(key=len)` | `sort` | 원래 단어들의 정렬 기준 |

길이가 같은 `banana`, `cherry`의 기존 순서는 유지된다. 이 문제의 정렬 결과는 `['kiwi', 'apple', 'banana', 'cherry']`다.

## 질문: key에 5가 들어간다면 sort(key=5)는 무슨 뜻일까?

**상황:** “key에 5, 4, 6, 6이 저장된다”는 해석을 말한 뒤, `sort(key=5)`가 되는 것인지 물었다. 앞선 설명에서 함수와 결과가 명확히 구분되지 않은 지점이었다.

**의도:** `len("apple")`의 결과 `5`가 정렬 호출의 어느 자리에 들어가는지 확인하려 했다.

**핵심 답변:** `key`에 전달하는 것은 `len` 같은 함수 자체다. `5`는 `sort`가 그 함수를 호출해 얻은 기준값이다. 실제로 `key=5`를 전달하면 숫자를 함수처럼 호출할 수 없어 오류가 난다.

```text
key로 전달한 함수: len
sort가 하는 호출: len("apple")
호출 결과: 5 → apple의 비교 기준으로 사용
```

이 흐름은 설명용으로 펼친 것이며, `key`라는 이름에 길이 여러 개를 차례로 대입하는 사용자 코드가 아니다.

## 질문: 반환값으로 정렬한다면 key라는 이름은 왜 필요할까?

**상황:** “결국 함수의 반환을 사용하는 거잖아. key가 왜 필요해?”라고 물었다. 이어 매개변수는 람다의 `x`가 아닌지 확인했다.

**의도:** 서로 다른 함수의 매개변수를 한 자리처럼 읽던 혼동을 해소하려 했다.

**핵심 답변:** `key`는 `sort`가 기준 함수를 받는 매개변수 이름이고, `x`는 전달한 람다가 단어 하나를 받는 매개변수다. 함수를 받는 자리와 단어를 받는 자리가 다르다.

```python
words.sort(key=lambda x: len(x))
#          key: sort의 자리
#                     x: 람다의 자리
```

## 질문: dict도 아닌데 왜 key가 나오고, sort(x=1)은 왜 안 될까?

**상황:** 사용자는 `key`를 보고 딕셔너리의 키를 떠올렸으며, `sort(x=1)`은 무엇을 뜻하는지도 물었다.

**의도:** `key`가 임의로 지은 이름인지, 함수가 정해 둔 이름인지 구분하려 했다.

**핵심 답변:** 여기서 정렬은 `sort`가 하는 일이다. `key`는 `sort`가 미리 정한 매개변수 이름이라 마음대로 바꿀 수 없다. 람다의 `x`는 직접 정의한 매개변수이므로 `word`로 바꿔도 된다.

```python
words.sort(key=lambda word: len(word))  # 같은 의미
# words.sort(x=1)는 지원하지 않는 매개변수 이름 때문에 오류
```

이 설명 뒤 사용자는 `key`가 그냥 임의 이름은 아니었다고 정정했고, “이해했다”고 말했다. 이는 당시 자기설명이며 새로운 문제를 독립적으로 푼 증거까지는 아니다.

## 질문: sort()는 인자를 안 줘도 요소를 하나씩 살펴보는 거였지?

**상황:** `key`를 구분한 뒤에도 17번에는 `map`이 필요하고 15번에는 필요 없는 이유를 다시 물었다. 이어 `sort()` 자체가 요소를 처리한다는 점을 확인했다.

**의도:** 고정된 한 문법의 암기에서, 각 함수가 맡는 실행 역할로 이해를 연결하려 했다.

**핵심 답변:** `words.sort()`는 `words` 자체가 정렬 대상이므로 별도의 리스트 인자가 필요 없다. `key`를 생략하면 단어 자체로 비교하고, `key=len`을 주면 길이를 비교한다. 요소를 처리하는 쪽은 여전히 `sort`다.

이날의 핵심 교정은 **함수 → 호출하는 쪽 → 반환값 → 반환값의 사용처**를 차례로 보는 것이었다. 정답 코드의 해설과 자기설명은 확인되지만, 이 대화에서 정렬 코드를 새로 실행한 결과는 확인하지 않았다.
