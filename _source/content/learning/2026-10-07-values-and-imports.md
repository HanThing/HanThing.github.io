복습 문제의 문장만으로 이해하기 어려운 부분을 실제 값과 내부 동작으로 풀어 달라고 요청한 기록이다. 아래 의도는 맥락에 따른 해석이며 예시는 당시 답변을 재구성했다. 이미 공개한 개념은 다시 만들지 않고 연결했다. 사용자의 실행 성공이나 숙련을 확인한 기록은 아니다.

## 질문: isna().mean()은 실제로 어떤 값을 반환하는가?

**상황:** 복습 문제에 나온 코드를 실제 값으로 보여 달라고 요청했다.

**의도:** 중간 불리언 표가 비율을 담은 Series로 바뀌는 과정을 확인하려는 질문이다.

**핵심 답변:** 4행 표에서 나이 열에 결측값이 1개, 점수 열에 2개 있다면 `df.isna()`는 각 칸의 결측 여부를 같은 크기의 불리언 DataFrame으로 반환한다. `.mean()`은 기본적으로 열마다 참을 1, 거짓을 0으로 평균 내므로 나이 `0.25`, 점수 `0.50`을 반환한다. 결과는 열 이름을 인덱스로 갖는 Series다. [[data/statistics-data-and-groups|결측 개수와 비율]]의 계산을 실제 값으로 다시 확인한 예다.

## 질문: 딕셔너리인데 왜 튜플을 언패킹한다고 하는가?

**상황:** 실제 값을 보여 달라고 요청한 뒤, 딕셔너리와 튜플은 다른데 왜 튜플 설명이 나오는지 물었다.

**의도:** 원래 자료구조와 반복 중 반환되는 한 항목의 자료형을 구분하려는 질문이다.

**핵심 답변:** `data={"사과":3,"바나나":5}`에서 `data.items()`를 순회하면 한 번에 `("사과",3)` 같은 키·값 튜플 하나를 받는다. `for key, value in data.items()`는 그 한 항목을 두 이름에 나눠 연결한다. 원래 `data`가 튜플로 바뀐 것은 아니다. [[learning/2026-09-18-collections-and-palindrome|딕셔너리 뷰와 항목 언패킹]]의 구분을 다시 적용한 질문이다.

## 질문: 주문 수에 관한 문장은 왜 관측이 아니라 근거인가?

**상황:** 매출 감소를 설명하는 문제에서 문장의 분류 이유를 물었다.

**의도:** 문장 자체의 내용과 앞의 결론에 대한 역할을 나누려는 질문이다.

**핵심 답변:** 주문 수 100건·주문당 1만 원에서 90건·1만 원이 되면 매출은 100만 원에서 90만 원으로 줄어든다. 주문 수와 평균 금액의 관측은 ‘매출 감소’라는 결론을 뒷받침하는 근거 역할을 한다. 다만 주문 수가 왜 줄었는지는 이 관계만으로 알 수 없다. 문장만 떼면 관측이기도 하므로 분류에는 앞뒤 맥락이 필요하다. [[data/interpretation|결과 해석과 결론의 범위]]로 연결한다.

## 질문: groupby와 agg는 실제로 어떤 표를 반환하는가?

**상황:** `orders.groupby('customer_id').agg(total_amt=('amount','sum'))`을 실제 값으로 설명해 달라고 한 뒤, 반환값이 Series인지 DataFrame인지 물었다.

**의도:** 집계 후 한 행의 의미, 인덱스와 열을 확인하려는 질문이다.

**핵심 답변:** 다음 설명용 표는 주문 5행을 고객 3행으로 줄인다. 이름 있는 집계는 `total_amt` 열을 가진 DataFrame을 반환한다. 열이 하나라는 이유로 Series가 되지는 않는다.

```python
import pandas as pd
orders = pd.DataFrame({
    "customer_id": [101, 102, 101, 102, 103],
    "amount": [1000, 2000, 3000, 5000, 4000],
})
summary = orders.groupby("customer_id").agg(total_amt=("amount", "sum"))
# customer_id가 인덱스: 101 → 4000, 102 → 7000, 103 → 4000
# summary.shape == (3, 1)
```

반면 `orders.groupby("customer_id")["amount"].sum()`은 Series를 반환한다. [[data/pandas-groupby-merge-reshape|집계의 반환 구조]]에 이어진다.

## 질문: 원래 orders에 고객별 합계 열을 붙이려면 어떻게 하는가?

**상황:** 새 요약표 대신 기존 주문 표에 값을 추가하는 방법을 물었다.

**의도:** 고객당 한 행으로 줄이는 집계와 원래 주문 행을 유지하는 계산을 구분하려는 질문이다.

**핵심 답변:** `orders.groupby("customer_id")["amount"].transform("sum")`은 원래 행에 대응하는 `[4000,7000,4000,7000,4000]`의 Series를 반환한다. `orders["total_amt"] = ...`로 대입할 때 열이 추가된다. `transform()` 호출 자체가 원본에 열을 추가하지는 않는다. [[learning/2026-10-01-hotel-segment-comparison|예약 구성비에서 쓴 transform]]과 같은 행 대응 원리다.

## 질문: 모듈·패키지·라이브러리는 왜 그렇게 부르는가?

**상황:** 구체적인 예를 요청한 뒤, 패키지를 여러 개 담은 디렉터리가 라이브러리인지와 라이브러리의 정확한 뜻을 연이어 물었다.

**의도:** 파일 개수에 따라 단계가 올라가는 분류인지 확인하려는 질문이다.

**핵심 답변:** `addition.py` 같은 파일은 모듈의 한 형태이며, 모듈·하위 패키지를 import 가능한 구조로 묶은 `calculator`는 패키지다. 라이브러리는 다른 코드가 재사용하도록 제공하는 기능 모음을 뜻한다. 같은 대상이 구조상 패키지이면서 계산 라이브러리일 수 있다. ‘모듈 여러 개 → 패키지 여러 개 → 라이브러리’라는 고정 계층은 아니다. [[learning/2026-09-18-frameworks|구조와 역할을 구분한 이전 기록]]에 연결된다.

## 질문: from 뒤에는 모듈과 패키지 모두 올 수 있는가?

**상황:** 가져오는 경로의 종류를 확인했다.

**의도:** 어디에서 무엇을 가져오는지 이름 수준에서 읽으려는 질문이다.

**핵심 답변:** `from calculator import addition`은 패키지의 하위 모듈, `from calculator.addition import add`는 그 모듈의 함수를 가져오는 예다. `from calculator import add`가 동작하려면 패키지에 해당 이름이 연결되어 있는 등의 조건이 필요하다. 내부 모든 함수가 자동으로 바깥 이름이 되는 것은 아니다. [[python/imports-and-packages|import의 실행과 이름 연결]]을 참고한다.

## 질문: __init__.py는 어떻게 함수를 패키지에 노출하는가?

**상황:** 초기화 파일을 다시 설명해 달라고 한 뒤, 내부에서 실제로 일어나는 동작을 더 자세히 요청했다.

**의도:** ‘노출’이라는 표현을 함수 객체와 이름 연결로 풀어 이해하려는 질문이다.

**핵심 답변:** 일반 패키지의 `__init__.py`는 패키지 모듈 객체의 이름 공간에서 실행된다. 그 안에 `from .addition import add`가 있으면 `addition`의 함수와 같은 객체를 패키지의 `add`라는 이름으로도 참조한다. 함수 코드를 복사하거나 덧셈을 미리 수행하는 것이 아니다.

```python
# calculator/addition.py
def add(a, b):
    return a + b

# calculator/__init__.py
from .addition import add

# 사용하는 코드
from calculator import add
result = add(3, 5)  # 8
```

처음 import할 때는 모듈 탐색과 객체 생성·등록·실행이 필요하며, 보통 이후 import는 `sys.modules`에 캐시된 객체를 쓴다. `def` 실행은 함수 객체를 만들고 이름을 연결하며, 함수 본문의 덧셈은 `add(3,5)`로 호출할 때 수행한다. 여기서는 명시적 재로딩이나 캐시 변경은 하지 않는 조건이다.
