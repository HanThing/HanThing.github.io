2026년 10월 15일, 타이타닉 생존 여부를 예측하는 미션의 전처리 코드를 읽으며 질문했다. 열을 없애는 이유는 무엇인지, 나이를 바꾸는 계산이 꼭 필요한지, 메서드를 이어 쓰면 중간에 어떤 값이 생기는지가 주된 관심이었다.

아래 의도는 대화 맥락을 바탕으로 정리했다. 작은 표와 숫자는 설명용으로 재구성한 예이며, 실제 타이타닉 데이터의 통계나 모델 실행 결과가 아니다. 이 기록에는 재학습·성능 개선·과제 제출의 증거를 포함하지 않는다.

## 질문: Ticket은 왜 버리는가? 그렇다면 Embarked도 불필요하지 않은가?

**상황:** 결측이 많은 `Cabin`을 제외하는 이유와 달리, `Ticket`을 불필요한 열로 설명한 근거가 궁금했다. 이어 승선항인 `Embarked`에도 같은 논리를 적용할 수 있는지 물었다.

**의도:** 예제에서 삭제한 열이라는 사실과, 예측에 쓸 정보가 없다는 판단을 구별하려는 질문이다.

**핵심 답변:** 티켓 문자열을 그대로 모델에 넣기 어렵다는 것과 그 정보가 쓸모없다는 것은 다르다. 티켓 번호의 크기를 생존 가능성의 크기로 해석할 근거는 없지만, 티켓을 공유하는 승객 수처럼 다른 형태로 바꿔 비교할 수 있다. 승선항도 유지가 정답으로 정해진 열은 아니며 같은 검증 조건에서 유용성을 확인해야 한다.

`Ticket`은 식별 성격의 값이고 `Embarked`는 승선항 범주다. 두 열을 모두 숫자로 바꿀 수 있어도 그 숫자의 의미는 다르다. `S → 0, C → 1, Q → 2`라고 바꿨다고 항구 사이에 크기나 두 배의 관계가 생기지는 않는다. 이런 코드를 어떻게 처리하는지는 모델의 방식과도 관련된다.

티켓 공유 인원 같은 파생 변수가 도움이 되는지, 승선항을 빼도 결과가 같은지는 당시 실행으로 확인하지 않았다. 열마다 다른 정보를 담으므로 한꺼번에 바꾸기보다 같은 데이터 분할·전처리·모델을 두고 하나씩 비교한다. 이 비교 기준은 후속 기록인 [[learning/2026-10-19-titanic-validation|타이타닉 검증과 전처리]]에서 이어진다.

## 질문: int(age_guess / 0.5 + 0.5) * 0.5는 무엇을 하는가?

**상황:** 그룹별 나이 중앙값을 구한 뒤 `guess_ages[i, j] = int(age_guess / 0.5 + 0.5) * 0.5`를 대입하는 줄에서 계산의 의미를 물었다.

**의도:** 숫자마다 무슨 역할을 하는지 계산 순서대로 확인하려는 질문이다.

**핵심 답변:** 여기서는 결측이 아닌 0 이상의 나이를 가까운 0.5 단위에 맞추려는 계산이다. 0.5 단위는 `22.0, 22.5, 23.0`처럼 반 살씩 차이 나는 값을 뜻한다. 이 식을 음수까지 통하는 일반 반올림 공식으로 쓰지는 않는다.

설명용 중앙값이 `22.3`이라고 하자.

| 순서 | 계산 | 결과 |
| --- | --- | ---: |
| 반 살을 한 칸으로 환산 | `22.3 / 0.5` | 44.6 |
| 가까운 칸을 고를 준비 | `44.6 + 0.5` | 45.1 |
| 양수의 소수 부분 제거 | `int(45.1)` | 45 |
| 다시 나이 단위로 환산 | `45 * 0.5` | 22.5 |

`int()` 자체가 반올림 함수인 것은 아니다. 이 식에서는 양수에 0.5를 더한 다음 소수 부분을 버리는 조합으로 가까운 칸을 고른다. 예를 들어 `22.25`처럼 두 칸의 가운데에 있는 값은 `22.5` 쪽으로 간다. 부동소수점 표현도 있으므로 모든 수에 대한 정확한 십진 반올림 도구로 일반화하지 않는다.

## 질문: 그냥 중앙값을 넣으면 안 되는가? 왜 굳이 0.5 단위로 맞추는가?

**상황:** 계산 방법을 들은 뒤에도 중앙값을 그대로 `guess_ages`에 저장하면 되지 않는지 다시 물었다. 반 살 단위라는 개념도 낯설다고 덧붙였다.

**의도:** 코드가 어떤 계산을 하는지와 그 계산이 반드시 필요한지를 따로 판단하려는 질문이다.

**핵심 답변:** 중앙값을 그대로 쓰는 선택도 가능하다. 0.5 단위로 맞추는 것은 별도의 표현 규칙이며 결측 대체의 필수 단계가 아니다. 중앙값을 반올림했다고 더 정확한 나이를 알아낸 것이거나 모델 성능이 좋아진 것은 아니다.

관측 나이가 `20, 21`이면 중앙값은 `20.5`다. 둘 다 정수여도 중앙값이 정수가 아닐 수 있다. 이미 중앙값이 정수나 `.5`로 끝나면 이 반 살 맞춤 계산으로 값이 달라지지 않는다. 반대로 `22.3 → 22.5`처럼 달라지면 원래 중앙값을 조금 바꾼 것이다.

그룹에 알려진 나이가 하나도 없다면 중앙값도 구할 수 없으므로 먼저 결측 상태를 확인해야 한다. 어떤 값을 채울지 정하는 문제와 숫자를 어느 간격으로 표현할지는 [[data/pandas-cleaning-validation|결측 처리와 검증]]처럼 나눠 생각한다.

## 질문: cut은 최솟값과 최댓값을 어떻게 아는가? AgeBand에는 정수가 들어가는가?

**상황:** `train_df['AgeBand'] = pd.cut(train_df['Age'], 5)`에서 다섯 구간을 만든다는 점은 이해했지만, 경계값을 알려 주지 않았는데 어떻게 나누는지 물었다. 이어 새 열의 값이 구간 번호인 정수인지 확인했다.

**의도:** 구간 경계를 정하는 방법과 각 행에 저장되는 값의 형태를 구별하려는 질문이다.

**핵심 답변:** 두 번째 인수에 정수 `5`를 주면 입력 나이의 범위를 이용해 폭이 같은 다섯 구간을 만든다. 기본 설정에서는 값이 들어간 **구간 자체**를 범주 값으로 돌려주며, 자동으로 `0~4`의 번호를 반환하는 것은 아니다. 번호가 필요하면 `labels=False`를 지정한다.

설명용 데이터와 결과는 다음과 같다. 기본값 `right=True`는 오른쪽 경계를 포함한다. 정수로 구간 수를 지정할 때는 끝값을 포함하도록 경계가 소폭 확장되므로 첫 경계가 정확히 0이 아닐 수 있다. [pandas.cut 공식 문서](https://pandas.pydata.org/docs/reference/api/pandas.cut.html)

```python
import pandas as pd

ages = pd.Series([0, 20, 40, 60, 80])
bands, edges = pd.cut(ages, 5, retbins=True)
codes = pd.cut(ages, 5, labels=False)
```

| 원래 나이 | 기본 구간 값 | `labels=False`의 번호 |
| ---: | --- | ---: |
| 0 | `(-0.08, 16.0]` | 0 |
| 20 | `(16.0, 32.0]` | 1 |
| 40 | `(32.0, 48.0]` | 2 |
| 60 | `(48.0, 64.0]` | 3 |
| 80 | `(64.0, 80.0]` | 4 |

`retbins=True`는 실제 계산된 경계도 함께 받아 확인하는 선택이다. 구간 번호 1은 한 살이라는 뜻이 아니다. 또한 `AgeBand`에 결과를 대입한 줄만으로 원래 `Age` 열까지 번호로 바뀌지는 않는다. 결측이나 지정 경계 밖의 값은 별도로 확인해야 한다.

한 열 선택이 Series인지 DataFrame인지는 [[data/pandas-dataframe-selection|Series와 열 선택]]에서, 직접 경계 목록을 지정하는 방식은 [[data/pandas-cleaning-validation|나이 구간의 경계]]에서 이어 읽을 수 있다.

## 질문: AgeBand로 묶은 집단의 Survived를 평균 내는 문장인가?

**상황:** `train_df[['AgeBand', 'Survived']].groupby(['AgeBand'], as_index=False).mean()`을 보고, 같은 나이 구간에 속한 집단의 `Survived` 값들을 평균 낸다고 설명하며 맞는지 확인했다.

**의도:** 열 선택, 그룹 지정, 계산을 한 문장으로 다시 풀어 확인하려는 질문이다.

**핵심 답변:** 그 설명이 이 코드의 계산을 짚는다. 두 열을 선택하고 `AgeBand`로 그룹을 정한 다음 `Survived`를 평균 낸다. `Survived`가 생존 1·사망 0이고 결측이 없다면 평균은 그 집단의 생존율이다.

설명용 한 구간의 값이 `[1, 0, 1, 1]`이면 합계 3을 인원 4로 나누므로 `0.75`, 즉 75%다. 평균 0.75가 ‘평균적인 생존 상태 0.75’라는 새 라벨을 뜻하지는 않는다. 결측이 있으면 기본 평균 계산에서 빠지는 값이 생기므로 분모가 전체 인원과 같은지 확인해야 한다.

`as_index=False`는 그룹 기준을 결과의 일반 열로 남기는 설정이다. 원본의 모든 승객에게 그 평균을 대입하는 코드가 아니며, 요약 결과를 만드는 코드다. [[data/pandas-groupby-merge-reshape|그룹 지정과 집계의 반환값]]에 같은 구분을 정리해 두었다.

## 질문: 승선항은 바로 map하면 안 되는가? mode()[0]은 무엇을 고르는가?

**상황:** 승선항의 최빈값을 구하고, `fillna(freq_port)`로 빈칸을 채운 뒤 `{'S': 0, 'C': 1, 'Q': 2}`로 매핑하는 코드를 보았다. 딕셔너리로 바로 바꾸면 안 되는지, `mode()[0]`은 최빈값 하나를 고른 것인지 물었다.

**의도:** 값의 변환과 결측 보완, 최빈값 계산과 첫 결과 선택을 구별하려는 질문이다.

**핵심 답변:** 일반 딕셔너리를 사용하는 이 예에서 `map()`은 대응하는 항구 문자를 숫자로 바꾼다. 사전에 없는 값은 결측이 되며, 빈 항구를 가장 흔한 항구로 추정해 주지 않는다. `fillna()`가 결측을 채우는 단계다. `mode()`는 최빈값들을 Series로 돌려주고 `[0]`은 그 결과의 첫 값을 선택한다.

아래는 `S`가 가장 흔하도록 만든 설명용 예다. 실제 데이터의 최빈값을 새로 계산한 결과는 아니다.

```python
ports = pd.Series(['S', 'C', None, 'S'])
mapping = {'S': 0, 'C': 1, 'Q': 2}

ports.map(mapping)  # [0.0, 1.0, NaN, 0.0]
freq_port = ports.dropna().mode()[0]  # 'S'
filled = ports.fillna(freq_port)
filled.map(mapping).astype(int)  # [0, 1, 0, 0]
```

이는 정렬을 위한 절차가 아니다. 결측이 남은 결과를 일반 `int`로 바로 바꾸면 오류가 날 수 있다. 또한 빈칸을 채웠어도 사전에 없는 다른 항구 표기가 있다면 매핑 뒤 결측이 다시 생길 수 있으므로 결과를 확인한다. [Series.map](https://pandas.pydata.org/docs/reference/api/pandas.Series.map.html), [Series.fillna](https://pandas.pydata.org/docs/reference/api/pandas.Series.fillna.html)

최빈값이 동률이면 `mode()`는 여러 값을 반환할 수 있다. `[0]`은 그중 첫 값이지 항상 유일한 최빈값이라는 보장이 아니다. 전부 결측이라 결과가 비었다면 첫 값을 꺼낼 수도 없다. [Series.mode](https://pandas.pydata.org/docs/reference/api/pandas.Series.mode.html)

모델을 검증할 때 이런 대체값은 학습 부분에서 구해 검증 부분에 적용한다. 원래 값을 복구한 것은 아니므로 최빈값 대체의 효과 역시 확인해야 한다. 이후의 [[learning/2026-10-19-titanic-validation|검증 단계에서 전처리를 맞추는 기준]]과 연결되는 지점이다.
