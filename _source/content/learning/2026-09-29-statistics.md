2026년 9월 29일 **통계시각화 실습 환경 설명** 대화에서 환경 설정과 Titanic 표 읽기를 시작으로, 분포·상관·결측치·미션 풀이까지 이어 갔다. “코드를 이해했다”에서 끝내지 않고 **직접 그래프를 작성할 수 있는가**, **내가 읽은 숫자의 방향과 조건이 맞는가**를 여러 차례 확인했다.

아래 질문 제목은 의미를 유지하며 다듬었고, **의도는 대화 맥락에서 해석**했다. 직접 답한 내용과 당시 설명자가 제시한 코드·수치를 구분했다. 화면 결과와 집계 수치는 보존된 대화 기록을 기준으로 하며, 이 글에서 노트북의 최종 실행·저장·제출을 새로 확인한 것은 아니다.

## 질문: 실습 환경과 데이터 로딩은 무엇을 준비하는 단계인가?

**상황:** 통계·시각화 노트북의 환경 설정과 데이터 로딩 부분부터 설명을 요청했다.

**의도:** 라이브러리와 설정을 먼저 이해하고, 이후에 쓰는 `df`가 어디서 왔는지 확인하려는 요청이다.

**핵심 답변:** NumPy는 수치 연산, pandas는 표와 집계, Matplotlib은 그림·축 관리, Seaborn은 통계 그래프를 맡는다. 표시 옵션을 바꾸는 것과 실제 데이터를 바꾸는 것은 다르다. 로딩 코드에서는 실제 Titanic 자료를 가져오는 경로와 실패 시 만든 합성 데이터 경로를 구분해야 한다.

합성 데이터는 난수와 정해 둔 생성 규칙으로 만든 연습 자료다. 행 수나 성별·등급별 패턴을 실제 Titanic 자료의 사실로 옮길 수 없다. 이후 대화에서는 실제 Titanic의 여섯 열을 고른 `(891, 6)` 표가 제시되었다.

## 질문: 샘플 수·피처 수·수치형 열·타깃을 이렇게 읽으면 맞나?

**상황:** 첫 체크포인트에서 표의 행·열 수와 dtype을 보고 직접 답했다. 범주형의 의미는 아직 모르겠다고 밝혔다.

**의도:** 화면에 보이는 정보를 분석 대상과 연결해 스스로 읽어 보려는 시도다.

**핵심 답변:** `shape`는 헤더를 제외한 데이터 크기다. 총 열 수와 타깃을 제외한 입력 열 수도 구분한다. 숫자 dtype을 의미상의 수치형 변수와 동일하게 세면 `pclass`·`survived`의 해석을 놓친다.

| 항목 | 실제 응답의 요지 | 피드백 |
| --- | --- | --- |
| 샘플 수 | 헤더 한 줄을 빼서 890개 | `(891, 6)`의 행 수는 이미 데이터 891개 |
| 피처 수 | 열이 6개 | 전체 열 6개, 생존 예측의 입력 후보는 타깃 제외 5개 |
| 수치형 열 | survived·pclass·age·fare 4개 | 숫자 dtype 기준은 맞음. 의미상 나이·요금은 양, 객실 등급은 순서 범주, 생존은 이진 범주 |
| 결측 열 | age와 embarked | non-null 수가 전체보다 적다는 판단은 맞음. non-null은 값이 올바르다는 보장은 아님 |
| 타깃 | survived, 나머지 값으로 예측 | 타깃과 입력을 구분한 설명이 맞음 |

이후 “자료형과 따로 변수 타입을 왜 분류하나?”를 물어, 계산 가능성과 해석 가능성의 차이로 이어졌다. [[data/statistics-data-and-groups|변수의 의미와 요약표]]에서 작은 예로 정리했다.

## 질문: 그래프를 혼자 그릴 수 있게 fig·axes와 각 인수를 설명해 줄 수 있나?

**상황:** 퍼짐 비교와 히스토그램·KDE를 배우면서, 별도 설명 자료보다 나중에 직접 문제를 풀 수 있도록 코드의 구성을 설명해 달라고 했다. `plt`와 `sns`가 같은 그림을 쓰는 이유도 물었다.

**의도:** 눈앞의 그림을 보는 것에서, 목적에 맞는 데이터를 골라 원하는 영역에 그리는 단계로 가려는 요청이다.

**핵심 답변:** `fig`는 전체 그림, `ax`는 그래프 영역 하나다. `data`·`x`는 사용할 값, `bins`는 히스토그램의 구간 수, `ax`는 그릴 장소를 정한다. Axes 수준 함수에서 `ax`를 생략하면 현재 영역을 사용한다.

설명을 들은 뒤 `data=df`, `x="age"`, `ax=ax`의 역할을 직접 풀어 말했다. 이어 작성한 코드는 다음과 같다.

```python
sns.histplot(data=df, x="age", bins=30, ax=ax)
```

인수 구성은 맞았지만 당시 질문은 **요금 `fare`를 30개 구간으로 그리는 것**이었다. 따라서 그 문제에 대한 교정은 `x="fare"`다. 문법을 이해한 부분과 요구한 열을 선택하는 부분을 나누어 피드백했다. `bins`도 정확히는 보이는 막대의 개수라기보다 **값을 나누는 구간 수**다.

[[data/statistics-distributions-and-plots|분포를 그리는 코드]]에 같은 평균·다른 퍼짐, 밀도 히스토그램과 KDE를 겹치는 코드, 현재 Axes의 역할을 연결했다.

## 질문: 사분위수와 실제 수염 끝은 다르지 않나? 로그를 씌우면 의미를 잃지 않나?

**상황:** `quantile()` 설명 뒤 IQR 경계가 실제 수염 끝과 다르다는 점을 짚었다. 이후 요금에 로그를 씌우면 눈속임처럼 보일 수 있고 원래 개수가 유지되는지도 물었다.

**의도:** 그림을 만드는 규칙이 원래 값을 어떻게 요약하거나 변환하는지 확인하려는 질문이다.

**핵심 답변:** IQR 경계는 계산한 기준선이고, 기본 박스플롯의 수염은 그 안에 있는 실제 관측값까지 간다. 로그 변환은 원 단위의 간격을 바꾸므로 원래 요금 그래프와 같은 의미로 읽을 수 없다. 관측을 없애는 것은 아니지만 구간 경계가 바뀌어 막대별 개수는 달라질 수 있다.

수염과 경계를 구분한 설명은 실제 응답에서 확인되었다. 이후 정리에는 Q1=10, 중앙값=20, Q3=30인 **편집용 숫자 예시**를 추가했다. 이 예시는 당시 사용자가 푼 문제로 기록하지 않았다. [[data/statistics-distributions-and-plots|IQR·수염·로그 변환]]에서 확인할 수 있다.

## 질문: corr 표와 결측치 표의 행 인덱스는 어디서 오는가?

**상황:** 상관행렬의 행·열 라벨과 내부 값의 차이를 질문했다. 결측치 요약표에서는 행 인덱스가 갑자기 생기는 것 같아 “질문을 더 해 달라”고 요청했다.

**의도:** 객체의 이름만 외우지 않고 원본 열 → 집계 Series → 요약 DataFrame으로 바뀌는 구조를 따라가려는 질문이다.

**핵심 답변:** `corr()`의 행·열 라벨은 비교하는 변수 이름이다. 결측치 집계 Series의 인덱스도 원본 열 이름이며, 이 Series를 DataFrame의 열로 넣으면 인덱스 라벨에 맞춰 행이 정렬된다. 요약 결과의 행은 더 이상 승객 한 명을 뜻하지 않는다.

## 퀴즈: 실제로 답한 구조·비율 확인 문제

당시 한 번에 한 단계씩 물었던 문제와 실제 응답이다.

| 당시 조건·문제 | 실제 응답 | 확인·교정 |
| --- | --- | --- |
| 100명 중 결측치 20개의 비율 | 0.2 | 맞음 |
| age·fare 각각 결측치 하나인 `isna().sum()` | 인덱스는 age·fare, 값은 각각 1 | 맞음 |
| counts 인덱스는 age·fare, ratios는 fare·age 순서. age의 ratio는? | 0.1 | 순서가 아니라 라벨로 대응시킨 답이 맞음 |
| count가 양수인 age·embarked만 남김 | 두 행·두 열 DataFrame | 맞음 |
| 그 표의 ratio를 막대로 그리면? | x는 age·embarked, 높이는 ratio | 맞음 |
| **결측치가 전혀 없다면**, `count > 0`으로 거른 결과의 `len`은? | 2 | 조건을 놓쳤음. 행이 없어 0 |
| 생존 80% 자료에서 전부 생존으로 예측하면? | 정확도 80% | 맞음 |
| -0.8과 +0.3 중 더 강한 선형 관계는? | -0.8, 절댓값이 더 큼 | 맞음. 방향 설명에는 “경향”이라는 조건을 더함 |

<details>
<summary>결측치가 없을 때의 shape과 len 교정</summary>

요약표에서 `count`와 `ratio` 두 열은 남아 있어도 `count > 0`인 행은 하나도 없다. 결과 shape은 `(0, 2)`, `len(missing)`은 행 수인 `0`이다. 열 수가 2인 것과 `len`은 다르다.

</details>

“행 인덱스가 왜 붙는지 이제 이해한 것 같다”는 자기 보고도 있었다. 이후 정렬 문제는 맞혔고 빈 결과 조건은 놓쳤으므로, 이를 전체 개념의 숙달로 확대하지 않는다. [[data/statistics-data-and-groups|라벨 정렬]]과 [[data/statistics-relations-and-interpretation|상관행렬]]에서 구조를 다시 볼 수 있다.

## 질문: 미션 코드에서 무엇이 문제이고, 그래프 이름은 어떻게 붙이나?

**상황:** 미션으로 넘어가 “마지막 데이터셋”이 따로 있는지 물었고, 범주별 반복 그림과 비율 그래프의 오류를 차례로 점검했다.

**의도:** 문제의 대상을 먼저 확인하고, 작성한 코드를 실행 가능한 그림 구성으로 고치려는 요청이다.

**핵심 답변:** 문제의 “마지막에 데이터셋을 요약”은 별도 데이터셋 이름이 아니라 현재 `df`를 요약하라는 뜻이었다. 오류는 변수와 문자열, 반복 대상의 짝, 반환 객체의 개수, 키워드 인수를 구분하며 고쳤다.

아래 오류 형태는 당시 답변에 남아 있는 화면 코드 설명을 재구성한 것이다. 현재 화면을 다시 확인한 결과나 최종 실행 성공 기록은 아니다.

| 점검한 코드 | 교정 이유·형태 |
| --- | --- |
| 그래프 영역과 열 이름을 함께 도는 반복문 | `for ax, col in zip(axes, ["sex", "pclass", "embarked"]):`로 짝을 만듦 |
| `x="col"` | 문자열은 이름이 col인 열을 찾음. 반복 변수의 값인 sex·pclass 등을 쓰려면 `x=col` |
| `plt.subplots(figsize=(8, 4))` 뒤 `axes[0]` | 반환되는 영역은 하나. 두 그림이면 `plt.subplots(1, 2, ...)` |
| `countplot(normalize=True)` | 이 함수에 `normalize`를 전달하는 형태가 잘못됨. `value_counts(normalize=True)`로 만든 비율을 `barplot(x=ratios.index, y=ratios.values)`로 그림 |
| `figsize(8, 4)` | 키워드 인수는 `figsize=(8, 4)` |
| 개별 그래프 제목 | `ax.set_title("제목")`; 전체 그림 제목은 `fig.suptitle("전체 제목")` |

## 질문: 나이 결측치를 평균으로 채우면 평균은 유지되고 퍼짐은 줄어들지 않나?

**상황:** 미션 5에서 결측치를 단순히 삭제하는 대신 나이의 평균으로 채우겠다고 제안하고, 평균은 유지되지만 표준편차는 줄어든다고 설명했다.

**의도:** 행을 보존하는 이점과 분포를 바꾸는 단점을 함께 고려한 제안이다.

**핵심 답변:** 관측된 값의 평균으로 채우면 그 **관측 평균**은 유지된다. 다만 결측된 사람의 실제 나이를 모르므로 원래 전체 집단의 평균을 복구했다고 말할 수 없다. 평균에 값이 몰리면 퍼짐과 다른 변수와의 관계도 달라질 수 있다.

이 응답은 평균 대체의 한계를 스스로 제시한 근거다. 당시 피드백에서는 중앙값·그룹별 대체 등도 비교하되 결측 원인과 분석 목적을 먼저 확인하고, 모델 평가용 데이터를 나눈 뒤 학습 데이터에서 대체값을 구하라고 보완했다. [[data/statistics-data-and-groups|평균 대체의 한계]]에 숫자 예를 남겼다.

## 질문: 생존율 방향을 맞게 읽었나? 박스가 겹치면 관계가 없는가?

**상황:** 미션 6의 근거 있는 관찰을 쓰며 “남성이 여성보다 생존율이 높다”, “pclass가 높을수록 생존율이 높다”고 말했다. 이어 박스플롯 해석을 요청했다.

**의도:** 집계·그림을 문장으로 옮기고, 중심과 퍼짐을 근거로 관찰을 쓰려는 시도다.

**핵심 답변:** 당시 제시된 집계는 여성 약 74.2%·남성 약 18.9%, 1등급 약 63.0%·2등급 약 47.3%·3등급 약 24.2%였다. 처음의 두 방향은 모두 교정했다. 객실 등급은 숫자가 작을수록 상위 등급이다.

이후 요금 박스의 세로 길이가 크다는 뜻을 **가운데 50%가 더 넓게 퍼져 있다**고 직접 설명했다. 이는 맞는 답이다. 당시 나이 박스는 많이 겹치고 생존자 쪽 요금의 중심 구간은 더 높다는 설명도 이어졌다. 다만 박스의 겹침만으로 나이와 생존의 모든 관계가 없다고 결론 낼 수는 없다.

다음 질문은 **가정**이었다. “1등급 안에서 생존 여부별 요금 분포가 거의 비슷하다면?”이라는 조건에, 요금·생존의 관계가 크지 않아 보이며 먼저 객실 등급에 따른 요금 관계를 확인하겠다고 답했다. 후속 확인 방향은 타당하지만 “**1등급 안에서는**”이라는 범위가 필요하다고 보완했다. 실제로 1등급만 분석해서 얻은 실행 결과로 기록하지 않는다.

[[data/statistics-relations-and-interpretation|상관과 그룹별 해석]]에 관측 비율, 중앙 구간의 겹침, 등급을 고정한 비교를 연결했다.

## 질문: 미션 8의 답을 근거와 함께 채워 줄 수 있나?

**상황:** 마지막 요약 미션은 답을 직접 채우고 근거를 설명해 달라고 명시적으로 요청했다.

**의도:** 앞서 확인한 품질·분포·관계를 한 편의 분석 요약으로 묶는 형태를 보려는 요청이다.

**핵심 답변:** 당시 답변은 자료 품질 → 단변량 분포 → 변수 간 관계 → 추가 확인 → 모델링 전 준비 순서로 예시 답안을 제시했다. 이는 **설명자가 제공한 답안**이며 사용자가 독립적으로 작성하거나 제출한 결과로 세지 않는다.

| 예시 답안의 근거 | 해석할 때 붙인 조건 |
| --- | --- |
| 나이 결측 177개, 승선 항구 결측 2개 | 각각 전체 891명 중 약 19.9%, 0.2%; 결측 처리 이유 필요 |
| 요금의 IQR 규칙 밖 값 116개로 당시 보고됨 | 고액 요금이라는 이유만으로 오류·삭제 대상으로 단정하지 않음 |
| 사망 549명·생존 342명 | 전부 사망으로 예측해도 정확도 약 61.6%; 정확도 하나로 평가하지 않음 |
| 성별·등급별 생존율과 요금 분포 차이 | 관측한 관계이며 인과를 확정하지 않음 |
| 같은 등급 안 비교, 성별과 등급 함께 보기, 연령대별 탐색 | 후속 분석 제안이며 완료된 결과는 아님 |

수치와 답안이 제시되었다는 사실과 노트북에 코드·답이 저장되었다는 사실은 다르다. 이 기록으로 확인할 수 있는 것은 질문, 실제 응답, 교정과 제공된 설명까지다.
