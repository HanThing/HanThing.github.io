DataFrame을 배울 때는 메서드 이름보다 **한 행의 의미, 반환되는 객체의 모양, 원본이 바뀌는 지점**을 먼저 본다. 이 글의 질문은 실제 대화에서 가져왔고, 의도는 문맥에 따른 해석이다. 작은 표는 설명을 위해 재구성했다. 실제 응답과 정정 과정은 [[learning/2026-09-29-dataframe|9월 28–29일 학습 기록]]에 남겼다.

## 질문: 이미 표인 데이터를 왜 다시 표로 만드는가?

**상황:** DataFrame 실습의 목표를 “표를 만든다”라고 설명하자, 원본부터 표인데 왜 또 만드는지, 그래프와 AI 학습은 어디에 연결되는지 물었다.

**의도:** 개별 문법을 외우기 전에 전체 작업의 목적과 결과물의 쓰임을 확인하려는 질문이다.

**핵심 답변:** 표라는 외형을 만드는 것이 아니라, **풀려는 문제에 맞게 한 행의 단위와 열의 의미를 바꾸는 것**이다. 고객 표는 고객당 한 행, 주문 표는 주문당 한 행, 행동 기록은 행동당 한 행일 수 있다. 다음 달 구매를 예측하려면 고객과 예측 기준 시점에 맞춘 입력표가 필요하다.

예를 들어 주문 두 행의 고객 번호가 같다면 고객 중복 오류가 아니라 한 고객의 주문 두 건일 수 있다. 이를 고객별 주문 횟수·알려진 구매금액 합계·마지막 주문일로 요약하면 행의 단위가 바뀐다. 예측 기준일 뒤의 구매를 입력에 섞으면 미래 정보를 미리 알려 주는 문제가 생기므로, 집계 기간도 정해야 한다.

그래프는 완성된 표를 꾸미는 마지막 단계만이 아니다. 분포가 이상하거나 특정 고객이 여러 번 나타나는 이유를 찾고, 원본 행을 조사할 단서를 준다. “퍼짐이 크다”는 말도 비교 대상·단위·중앙값·분위수 등의 근거를 함께 제시해야 한다. 관찰, 가능한 설명, 추가 확인, 처리 결정을 구분한다. [[data/eda-and-causality|EDA와 해석의 범위]]와 연결된다.

## 질문: NumPy도 표를 만들 수 있는데 왜 Pandas를 쓰는가?

**상황:** NumPy 배열로도 행과 열을 만들 수 있으니 DataFrame의 별도 역할이 불분명했다. `tabular`를 튜플과 연결해서 이해하기도 했다.

**의도:** 데이터의 형태, 파이썬 객체, 그 객체를 다루는 라이브러리를 나누려는 질문이다.

**핵심 답변:** `tabular data`는 행과 열로 된 데이터라는 뜻이고 특정 라이브러리 이름이 아니다. Pandas는 도구 모음이고, DataFrame은 그 도구가 제공하는 2차원 표 객체다. NumPy 배열은 수치 배열 계산에, Pandas는 이름이 있는 열·행 인덱스·서로 다른 열 자료형·조건 선택·그룹 집계·키 결합을 다루는 데 편리하다.

| 이름 | 이 실습에서 맡은 역할 |
|---|---|
| NumPy | 배열과 수치 계산 |
| Pandas | 표 읽기, 선택, 정리, 집계, 결합 |
| Matplotlib | 그래프와 축의 세부 표현 |
| Seaborn | Matplotlib을 바탕으로 통계 그래프 표현 |
| EDA | 이 도구들로 질문하고 데이터를 조사하는 활동 |

NumPy의 보통 `ndarray`는 배열 전체의 dtype 하나를 사용한다. DataFrame은 열마다 dtype을 가진다. 이는 NumPy로 혼합 정보를 절대 표현할 수 없다는 뜻이 아니라, 표 조작에 제공되는 인터페이스가 다르다는 뜻이다. [[data/numpy-array-axes|배열의 축과 모양]]을 떠올리되 Pandas의 이름표와 정렬 규칙까지 같다고 가정하지 않는다.

재현 가능한 파이프라인은 입력, 처리 규칙과 순서, 기준 날짜, 환경 등을 남겨 결과를 다시 확인할 수 있는 흐름이다. 같은 결과가 반복된다고 그 결과가 옳다는 뜻은 아니다. EDA 중 형식을 고쳐 다시 조사할 수도 있으므로 “가공했으니 EDA가 끝났다”처럼 둘을 배타적으로 나누지 않는다.

## 질문: 인덱스는 기본키인가? 표를 만드는 문법은 열 기준뿐인가?

**상황:** 고객 표 왼쪽의 `0, 1, 2`와 `customer_id`를 함께 보고, 기본키를 행 이름으로 이해했다. 딕셔너리로 만드는 표가 열 중심이라는 점은 설명했지만 행 중심 생성 방법도 물었다.

**의도:** 화면의 행 번호, 데이터의 식별자, 생성 코드의 자료구조를 구분하려는 질문이다.

**핵심 답변:** 인덱스는 Pandas가 행을 식별·선택·정렬하는 데 쓰는 레이블이며 중복될 수도 있다. 업무상 기본키는 각 대상을 유일하게 구분하고 결측이 없어야 한다. `customer_id`가 그 조건을 충족하는지는 검사해야 하고, 이름·도시·소득이 모두 식별키가 되는 것은 아니다.

```python
import pandas as pd

# 열 이름 → 그 열의 값들
customers = pd.DataFrame({
    "customer_id": [101, 102],
    "name": ["Alice", "Bob"],
})

# 한 리스트가 한 행
same_table = pd.DataFrame(
    [[101, "Alice"], [102, "Bob"]],
    columns=["customer_id", "name"],
)
```

기본 생성에서는 인덱스가 `0, 1`로 붙지만 `customer_id`는 일반 열이다. `shape`은 `(행 수, 열 수)`, `columns`는 열 레이블, `dtypes`는 열별 자료형이다. `head()`는 앞부분만 돌려준다. `info()`의 비결측 개수는 값의 유효성 검사와 다르다. 예를 들어 `"bad-date"`는 문자열로 존재하므로 그 상태에서는 결측으로 세지 않는다.

숫자로 저장된 고객 번호도 측정량은 아니다. 평균 고객 번호는 대개 해석할 의미가 없다. 반대로 `"55,000"`처럼 숫자처럼 보이는 문자열은 바로 수치 계산에 쓰기 어렵다. [[data/pandas-cleaning-validation|자료형 변환과 검증]]에서 이어서 다룬다.

## 질문: Series는 튜플이나 딕셔너리인가? 대괄호 하나가 왜 결과를 바꾸는가?

**상황:** `orders["amount"]`는 Series라는 말을 들었지만 Series 자체의 설명이 부족했다. `columns = ["amount"]`가 실제 데이터를 담는지, 이후 `orders[columns]`가 무엇인지도 혼동했다.

**의도:** 문법의 모양을 외우기보다 각각의 표현식이 만드는 객체를 확인하려는 질문이다.

**핵심 답변:** Series는 인덱스가 붙은 1차원 데이터 객체다. 인덱스와 값을 묶은 튜플들의 리스트나 파이썬 딕셔너리와 같은 타입은 아니다. 하나의 열 이름 문자열로 선택하면 Series, 열 이름의 리스트로 선택하면 DataFrame을 받는다.

```python
orders = pd.DataFrame({
    "customer_id": [101, 103, 105],
    "amount": [12000, 8000, 19000],
})

orders["amount"]       # Series, shape (3,)
orders[["amount"]]     # DataFrame, shape (3, 1)

columns = ["amount"]   # 열 이름 문자열 하나가 들어 있는 파이썬 리스트
orders[columns]         # 위의 orders[["amount"]]와 같은 선택
```

바깥 `[]`는 DataFrame에 선택 대상을 전달하는 문법이고, 안쪽 `[]`는 열 이름 리스트를 만드는 문법이다. 세 열을 고르면 행은 그대로 두고 세 열짜리 새 결과를 받는다. 원본의 나머지 열을 삭제하는 코드가 아니다.

Series에는 dtype 하나가 있다. 혼합 값을 넣으면 공통으로 표현할 수 있는 자료형으로 맞추거나 `object` 같은 자료형을 사용할 수 있다. “1차원”은 모든 값이 동일한 파이썬 클래스라는 뜻은 아니며, 내부가 반드시 파이썬 리스트라는 뜻도 아니다.

## 질문: 비교 결과는 무엇이고, 왜 and 대신 &와 괄호를 쓰는가?

**상황:** `loc`의 입력 개수와 마스크의 실제 값을 물었다. `&`가 반복 가능한 객체라면 어디에나 적용되는지, 조건을 감싼 괄호가 튜플을 만드는지도 질문했다.

**의도:** 조건식에서 행 선택까지 한 번에 설명하지 않고 중간 반환값을 확인하려는 질문이다.

**핵심 답변:** 열과 숫자의 비교는 각 원소를 비교한 불리언 Series를 만든다. 이를 `.loc[행 선택, 열 선택]`의 행 자리에 넣으면 True인 행을 선택한다. `&`와 `|`는 Series의 조건들을 원소별로 결합한다. 괄호는 연산 우선순위를 명확히 한다.

```python
mask = (orders["customer_id"] == 103) | (orders["customer_id"] == 105)
# 인덱스 0 → False, 1 → True, 2 → True

result = orders.loc[mask, ["amount"]]
# 인덱스 1, 2를 유지하는 2행 × 1열 DataFrame
```

이 조건은 “103이거나 105”이다. 한 값이 동시에 두 번호라는 뜻이 아니다. `mask`를 만드는 줄은 행을 제거하지 않고, `.loc`가 선택 결과를 돌려주며, 대입이 그 결과에 이름을 붙인다.

파이썬의 `and`·`or`는 피연산자 전체의 참·거짓을 판단한다. 여러 불리언을 가진 Series에 이를 그대로 적용하면 참·거짓을 하나로 결정할 수 없어 오류가 난다. `&`는 정수의 비트 연산, 집합의 교집합 등 다른 타입에서도 쓰이는 연산자이며, 일반 리스트에 원소별 논리를 자동 적용하는 문법은 아니다.

| 선택 | 기준과 결과 |
|---|---|
| `orders.loc[mask]` | True인 행, 모든 열 |
| `orders.loc[mask, "amount"]` | True인 행의 amount Series |
| `orders.loc[mask, ["amount"]]` | True인 행의 한 열짜리 DataFrame |
| `orders.iloc[0:2, 0:1]` | 위치 기준 앞 두 행·첫 열, 끝 위치는 제외 |

`loc`는 레이블을, `iloc`는 정수 위치를 사용한다. 불리언 마스크가 언제나 행 전용인 것도 아니다. 어느 자리에 전달했는지를 함께 봐야 한다. Series 마스크와 열 대입은 인덱스 정렬이 개입할 수 있으므로 처음에는 대상 표에서 직접 만든 마스크를 사용하면 대응 관계가 명확하다.

노트북에서 셀 마지막의 `result`나 `orders.head()`는 결과가 표시될 수 있다. `result = ...`는 저장하는 대입문이고, 중간 결과를 확실히 표시하려면 `display(result)`를 사용한다. 반환과 출력은 같은 동작이 아니다.

## 퀴즈: 선택 결과를 먼저 말하기

다음은 복습용으로 추가한 문제이며 당시 사용자의 답변이 아니다.

```python
mask = (orders["customer_id"] == 101) | (orders["customer_id"] == 105)
a = orders.loc[mask, "amount"]
b = orders.loc[mask, ["amount"]]
```

`mask`, `a`, `b`의 타입과 길이 또는 shape은 무엇인가? 원본 주문 표의 행은 줄어드는가?

<details>
<summary>정답과 이유</summary>

`mask`는 길이 3의 불리언 Series이고 값은 `[True, False, True]`이다. `a`는 길이 2의 Series, `b`는 shape `(2, 1)`인 DataFrame이다. 둘 다 원본 인덱스 `0, 2`를 가진다. 이 코드에는 원본에서 행을 삭제하는 대입이나 연산이 없으므로 `orders`는 3행 그대로다.

</details>
