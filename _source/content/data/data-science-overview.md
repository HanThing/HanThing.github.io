“매출을 분석해 주세요”라는 요청만으로는 필요한 작업을 정할 수 없습니다. 비교할 기간과 취소 주문의 처리 기준, 결과로 내릴 결정을 먼저 정해야 합니다.

[6개 챕터 학습판 열기](https://hanthing.github.io/learning/data-science-overview.html)

## 개념 지도

질문 정의 → 수집 → **[[data/observation-unit|행과 열의 의미 확인]]** → **[[data/data-quality|품질 진단]]** → **[[data/wrangling|변형·집계]]** → **[[data/eda-and-causality|탐색과 가설 확인]]** → **[[data/interpretation|근거와 한계 전달]]**

프로그램은 반복을 처리하고, 통계는 불확실성을 해석하며, 도메인 지식은 취소·환불 같은 현장의 의미를 정합니다.

| 질문 | 접근 | 결과의 예 |
|---|---|---|
| 무슨 일이 있었나? | 기술적 분석 | 지난달 매출 합계와 변화율 |
| 왜 달라졌나? | 진단적 분석 | 상품·고객군별 차이와 원인 후보 |
| 앞으로 어떻게 될까? | 예측적 분석 | 판매량 추정과 오차 범위 |
| 무엇을 해야 할까? | 처방적 분석 | 비용·재고·공급 시간을 반영한 주문량 |

판매량 예측만으로 재고 주문량이 정해지지는 않습니다. 현재 재고와 품절 손실 같은 제약을 함께 봐야 합니다. 모든 질문에 머신러닝이 필요한 것도 아닙니다. 합계를 묻는 질문에는 집계가 먼저입니다.
