벡터를 배열로 저장한 뒤 **길이·방향·결합 방식 중 무엇을 계산하는지** 구분하는 노트다. 아래 의도는 실제 대화 맥락에서 해석했다. 직접 설명한 내용과 아직 독립 적용을 확인하지 못한 내용은 [[learning/2026-09-23-numpy-and-tensors|학습 기록]]에 구분했다.

## 질문: 두 벡터를 빼는 것이 왜 거리와 연결되는가?

**상황:** 벡터 단원에서 두 끝점 사이의 거리를 읽고, 두 벡터의 차이가 한 끝점에서 다른 끝점으로 이동하는 벡터라는 설명을 직접 제시했다.

**의도:** 거리 공식을 외우기보다 빼기와 길이의 관계를 확인하려는 질문이다.

**핵심 답변:** `a=[1,2]`, `b=[4,6]`이면 `b-a=[3,4]`는 a에서 b로 가는 이동이다. 그 길이 `sqrt(3²+4²)=5`가 두 점 사이 거리다. 반대로 빼면 방향은 반대지만 길이는 같다.

```python
import numpy as np
a = np.array([1, 2])
b = np.array([4, 6])
np.linalg.norm(b - a)  # 5.0
```

`[3,4]`는 성분이 두 개인 수학적 2차원 벡터지만 NumPy에서는 `shape=(2,)`, `ndim=1`인 배열이다. 수학적 공간의 차원과 [[data/numpy-array-axes|배열의 축 수]]를 구분한다.

## 질문: 행렬의 * 연산도 행렬곱이라고 생각했는데, 무엇이 다른가?

**상황:** 행렬곱 단원으로 넘어가며 `*`를 행렬곱이라고 생각했다고 밝혔다.

**의도:** 연산 기호가 바뀌면 원소를 결합하는 방식이 어떻게 달라지는지 확인하려는 질문이다.

**핵심 답변:** `*`는 대응하는 원소끼리 곱한다. `@`는 1차원 배열끼리면 내적, 2차원 배열끼리면 행렬곱이다. 행렬곱에서는 왼쪽의 한 행과 오른쪽의 한 열을 곱해 더한다.

```python
A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
A * B  # [[5, 12], [21, 32]]
A @ B  # [[19, 22], [43, 50]]
# (A @ B)[0, 0] = 1*5 + 2*7 = 19
```

`(N,D) @ (D,H) → (N,H)`에서 D는 곱한 값을 더하며 사라지고 N과 H는 남는다. 식으로는 `Y[i,j] = sum(X[i,k]*W[k,j] for k in range(D))`다. 맞아야 하는 두 D는 내적의 성분 수다. [[data/numpy-broadcasting|브로드캐스팅]]의 “같거나 1” 규칙으로 대체할 수 없다.

설명용 성적 예에서 `scores=[[80,60],[50,90]]`, `W=[[.5,.2],[.5,.8]]`이면 `scores@W=[[70,64],[70,82]]`다. W의 각 열이 하나의 평가 기준이다. 이것이 [[data/numpy-linear-layers|선형층]]의 입력별 가중치와 연결된다.

## 질문: 코사인 유사도에서 norm은 왜 axis=1인가? query에도 axis=1을 쓰는가?

**상황:** `E.shape=(100,64)`, `query.shape=(64,)`인 검색 문제에서 행별 norm과 query의 norm을 계산하려 했다. 샘플 100개가 있는 축과 길이를 계산할 축을 혼동하기 쉬운 지점이었다.

**의도:** 축 이름 대신 실제로 합쳐지는 성분을 기준으로 계산하려는 질문이다.

**핵심 답변:** E의 각 행이 벡터 하나라면 64개 성분을 제곱해 더해야 한다. 따라서 마지막 축인 `axis=1`을 줄여 길이 100개를 얻는다. query는 1차원이므로 axis=1 자체가 없다.

```python
# 각 행과 query가 모두 영벡터가 아니라는 전제
similarities = (E @ query) / (
    np.linalg.norm(E, axis=1) * np.linalg.norm(query)
)
best_index = np.argmax(similarities)
best_vector = E[best_index]
```

`np.linalg.norm(E)`처럼 축 없이 이 2차원 배열 전체에 적용하면 기본적으로 전체 원소의 제곱합에 루트를 씌운 스칼라를 얻는다. 각 행의 길이가 아니다. `axis=0`은 샘플들을 가로질러 feature별 길이를 구하므로 목적이 다르다.

`argmax`의 반환값은 최고 점수가 아니라 **그 점수의 인덱스**다. 실제 검색에서는 같은 인덱스의 문서나 항목을 가져온다. query를 그 숫자로 바꾸는 연산이 아니다.

## 질문: a / b * c는 a / (b * c)와 같은가?

**상황:** 코사인 유사도의 분모에 두 norm을 넣는 코드를 작성하다 연산 순서를 물었다. 이후 `nplinalg.norm(query)`라는 이름 오류도 나타났다.

**의도:** 수식의 분모 전체를 파이썬으로 옮기는 방법과 코드 오류 위치를 구분하려는 질문이다.

**핵심 답변:** `*`와 `/`는 우선순위가 같고 왼쪽부터 계산한다. `a/b*c`는 `(a/b)*c`다. 분모가 `b*c`이면 괄호가 필요하다. 라이브러리 호출은 점을 포함한 `np.linalg.norm(query)`다.

이 두 오류는 각각 연산 순서와 이름 접근의 문제다. 공식을 아는 것만으로 올바른 코드가 보장되지 않는다.

## 질문: 표준화와 norm으로 나누기는 무엇이 다른가? 길이가 1이면 원래 정보는 사라지는가?

**상황:** 표준편차로 나눈 앞 실습과 벡터 길이로 나누는 검색 실습을 비교했다. 정규화한 벡터가 기저인지, 길이가 없어지는 것인지, 원래 정보가 어떻게 되는지도 물었다.

**의도:** 비슷하게 보이는 나눗셈이 서로 다른 정보를 보존한다는 점을 이해하려는 질문이다.

**핵심 답변:** feature별 표준화는 `(X-평균)/표준편차`로 각 특성의 기준과 척도를 맞춘다. L2 정규화는 각 벡터를 자기 길이로 나눠 **방향은 유지하고 길이를 1로 만든다.** 길이가 없어지는 것은 아니며, 정규화 결과만 남기면 원래 크기를 복원할 수 없다.

`[3,4]/5`와 `[6,8]/10`은 모두 `[.6,.8]`이다. 원래 길이를 따로 저장하면 복원이 가능하다. 길이 1이라는 조건만으로 기저가 되지는 않는다. 기저에는 선형 독립성과 공간을 생성한다는 조건이 필요하다.

query가 `[1,0]`일 때 `[1,0]`과 `[10,10]`의 내적은 1과 10이다. 큰 크기가 점수에 영향을 준다. 코사인 유사도는 각각 1과 약 0.707이므로 방향의 가까움을 비교한다. **두 벡터 모두 단위 벡터일 때 내적과 코사인 유사도가 같다.** 영벡터는 방향을 정의할 수 없어 이 식으로 나누면 안 된다.

## 질문: keepdims가 없으면 왜 안 되는가? axis=0으로 나누거나 전치하면 되는가?

**상황:** query 10개와 임베딩 1,000개를 한꺼번에 비교하는 문제에서 행별 norm의 `(10,)`과 `(10,1)` 차이, 전치를 통한 해결 가능성을 물었다.

**의도:** 각 벡터에 자기 길이가 적용되도록 shape을 맞추려는 질문이다.

**핵심 답변:** `(10,64)`를 행별 길이 `(10,1)`로 나누면 각 행의 64개 성분에 같은 길이가 적용된다. `(10,)`은 오른쪽 정렬에서 64와 충돌한다. 1차원 배열의 `.T`는 shape을 바꾸지 않는다. axis=0은 계산 대상 자체를 바꾼다.

```python
# Q: (10,64), E: (1000,64); 각 행의 norm > 0
Qn = Q / np.linalg.norm(Q, axis=1, keepdims=True)
En = E / np.linalg.norm(E, axis=1, keepdims=True)
S = Qn @ En.T        # (10,1000)
best = S.argmax(axis=1)  # query마다 후보 인덱스 하나: (10,)
```

`.T`가 필요한 곳은 마지막 행렬곱이다. 후보 벡터들을 열로 놓아 query 한 행과 후보 한 열을 내적한다. 축 유지 자체는 [[data/numpy-shape-views|None과 shape 조작]], 나눗셈의 재사용은 [[data/numpy-broadcasting|브로드캐스팅]]의 역할이다.

## 퀴즈: 행별 단위 벡터의 유사도 표는 어떤 shape인가?

정리 과정에서 만든 보충 문제이며 사용자 응답 기록은 없다. A는 `(4,6)`, B는 `(9,6)`이고 각 행의 길이는 1이다. 모든 A 행과 B 행 사이의 코사인 유사도를 계산하는 식과 결과 shape은?

<details>
<summary>정답과 이유</summary>

`A @ B.T`, shape은 `(4,9)`다. 길이가 이미 1이므로 각 내적이 코사인 유사도다. `A*B`는 모든 쌍을 비교하는 행렬곱이 아니다.
