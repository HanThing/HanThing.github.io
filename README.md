# HanThing — 지식 지도와 복습

첫 화면의 3차원 지도는 공개 지식 문서마다 노드 하나를 표시합니다. 보이는 검색·종류 필터와 최근 글에서 노트를 찾고, 헤더의 ‘노트 찾기’로 여는 탐색 패널에서 과정·수업을 좁힙니다. 요약 패널에서 원문과 퀴즈·플래시카드로 이동합니다. Markdown에서 생성한 실제 노트와 연결만 표시하며 장식용 노드·선은 없습니다. 과정 참고 문서는 지식 노드에 포함하지 않습니다. 한 번의 학습 정리에서 주제별 문서 여러 개를 만들거나 기존 문서를 갱신할 수 있습니다.

스크롤할 때만 입자들이 실제 노드에서 퍼지고 돌아옵니다. 같은 노드의 투영 좌표를 공유하고, 산개 전 입자 그리기와 전체 화면 블러 합성을 생략합니다. 퍼짐 정도는 스크롤을 부드럽게 따라갑니다. 드래그로 회전하고 버튼으로 확대합니다. 휠·세로 터치는 페이지를 스크롤합니다. 밝게/어둡게 설정을 본문·복습 화면과 공유하며, 움직임 줄이기 설정과 일시정지를 지원합니다. 하단의 기록·질문·학습 세트는 더 보기와 접기로 조절합니다.

노트 목록은 과목 → 수업 → 개념 순이며 날짜별 질문 기록은 관련 개념 아래에 연결합니다. `courseId`·`lessonId`는 원래 배운 수업이고 `topics`는 관련 주제입니다. 공식 과정은 자료가 없는 경우에도 선택할 수 있으며 빈 결과를 표시합니다.

종류 필터로 날짜별 기록을 고르면 개념 아래에 연결된 기록 자체도 목록에 나옵니다. 최근 글은 `published` 또는 `date`를 사용합니다. `/?note=<노트 ID>`는 해당 노드와 직접 연결된 노트를 강조하며, 전체 보기로 돌아갈 수 있습니다. 노트 ID는 콘텐츠 루트 기준 확장자 없는 경로입니다.

## 복습 자료와 진도

`review-data.json`에는 공개 노트를 바탕으로 NotebookLM에서 생성하고 검토한 퀴즈·플래시카드가 들어갑니다. 방문자는 로그인 없이 `review.html`에서 풀 수 있습니다. 사이트는 문제를 풀 때 AI를 호출하지 않습니다.

- 관련 개념 노트와 날짜별 기록은 같은 주제별 학습 세트를 공유합니다. 퀴즈의 표시·제외는 문제 단위이며, 개념의 익힘 기록은 학습 목표 단위입니다.
- 세트의 `noteIds`가 글과 복습의 연결 기준입니다. 공통 글 화면은 제목 옆·하단에 실제 퀴즈·카드 개수와 `review.html?set=…&mode=quiz|cards&from=<노트 ID>` 링크를 생성합니다. `from`이 유효한 공개 노트면 복습 상세를 열지 않아도 원문으로 돌아갈 수 있으며, 방식 전환에도 원문 연결을 유지합니다.
- 기본 화면은 복습 시작 → 한 문제 → 답·해설 확인 → 다음 문제입니다. 다섯 문제 제한 없이 이어 풀며 언제든 ‘여기서 마치기’로 끝냅니다. 일반 진입은 전체 주제이며, 글에서 들어온 경우 해당 세트와 원문 복귀 링크를 유지하고 ‘모든 주제로 복습’으로 범위를 넓힐 수 있습니다.
- 상단에는 현재 범위에서 제외하지 않은 복습 대상·풀어본 고유 문항·기한 도래 문항 수와 미풀이·대기·제외 수를 표시합니다. 재풀이는 풀어본 문항 수를 늘리지 않습니다.
- `questionQueue()`는 미풀이와 기한 도래 문항을 1:1로 교대합니다. 복습은 오래 기다린 순서, 새 문제는 기존 출처·목표 분산 순서이며 한쪽이 없으면 다른 쪽을 계속 냅니다. 매 문항 이동 때 다시 선정하고 `lastQuestionKind`로 짧은 재방문에서도 교대를 유지합니다.
- 문항 답안의 `dueAt`·`intervalDays`는 도움 없는 첫 정답 1일, 예정 복습 정답 3→7→21일(이후 21일), 오답·힌트·정답 보기 10분을 적용합니다. 일정이 없는 과거 답안은 답변 시각 기준으로 보완합니다. 미래 문항은 기본 출제에서 빠지고, 명시적으로 예정일 전 연습을 켜면 현재 대상이 없을 때 추가로 풉니다. 조기 정답은 원래 복습일·간격을 유지합니다.
- ‘다시 보기’와 ‘이 문제 제외’는 선택 사항입니다. 정답을 맞혀도 자동 제외하지 않습니다. 상세의 ‘다시 볼 문제만’ 필터와 ‘퀴즈에서 제외한 문제’ 복원을 지원합니다. 제외는 카드·같은 개념의 다른 문제·노트·과거 답안에 영향을 주지 않습니다.
- 연습 정답 후 최소 24시간이 지나 별도 점검문항을 도움 없이 맞히면 익힘으로 기록합니다. 이후 점검을 통과할 때마다 3일 → 7일 → 21일로 간격을 늘리고, 그 뒤에는 21일마다 확인합니다. 이는 사이트의 단순 운영 기준이며 연구에서 정해 준 최적 공식은 아닙니다. 새 회차를 즉시 열어도 시간 조건을 건너뛸 수 없습니다.
- 오답·카드의 ‘다시 볼래요’는 홈의 예정 복습 추천과 개념 상태에 반영합니다. 힌트·정답 확인과 카드의 ‘알겠어요’만으로 익힘이 되지는 않습니다.
- 진도는 현재 기기·브라우저의 로컬 저장소에만 남습니다. 기존 `hanthing-review-v1` 키의 기록·회차·목표 상태는 유지하며 스키마 2로 읽습니다. 날짜가 없는 과거 점검 대기에는 이관 시점부터 1일, 과거 익힘에는 3일의 간격을 부여합니다. 저장을 사용할 수 없어도 풀이는 가능합니다.
- 목표 버전과 생성본 버전을 구분합니다. 새 문제를 가져와도 관련 없는 목표의 진도를 초기화하지 않습니다. 문제별 표시·제외는 `questionPreferences`의 `[set.id, set.version, question.id]` 키로 보관하므로 새 생성본에 이전 제외가 잘못 적용되지 않습니다.
- 홈의 예정 복습 추천은 `getReviewQueue(sets, state, { limit: 5, now: Date.now() })`의 미리보기 제한을 유지합니다. 결과는 상태를 수정하지 않으며 제외한 문제를 건너뜁니다. `review.html?set=…&goal=…`는 해당 목표를 먼저 풀고 같은 세트의 나머지 문제로 이어집니다.
- 상태 회귀 확인: `node --test blog-preview/review-state-check.mjs`. 로컬 조립·서버 실행 후 화면 회귀 확인: `python3 blog-preview/review-ui-check.py --aside http://127.0.0.1:8876/review.html` (기존 로컬 기록을 저장·복원).

## 공개 원본 유지

Markdown 원본은 `_source/content/`입니다. `content-data.js`는 여기에서 생성됩니다. `_source/AGENTS.md`, `_source/INDEX.md`, `_source/CHANGELOG.md`를 읽고 공개 글을 수정한 뒤 실행합니다.

```sh
sh _source/rebuild.sh
```

이 명령은 글과 카탈로그를 재빌드합니다. NotebookLM 문제 재생성·커밋·배포는 하지 않습니다. 학습 내용이 바뀌면 영향받은 목표의 퀴즈·카드만 별도로 생성하고, 지정한 생성물 ID의 내보내기를 검토한 후 연결합니다. 기존 검증본은 새 생성본 검토가 끝날 때까지 보존합니다.

발행 전에는 새 글의 메타데이터·복습 매핑·관련 글의 근거를 확인합니다. 공통 화면이 생성하는 탐색을 Markdown에 복사하지 않습니다. 복습이 빠진 공개 지식 노트는 검사 실패로 처리하고, 없는 자료의 링크나 개수를 만들지 않습니다. 관련 카드의 설명은 검토한 관계 이유 또는 명시된 노트 요약입니다.

실제 렌더링 화면에서 홈 검색·종류 필터 → 글 → 퀴즈·카드 → 원문 복귀 → 관련 글·해당 노드 지도까지 확인합니다. 빌드와 데이터 검사는 이 화면 확인을 대신하지 않습니다. 초안은 공개 카탈로그·색인·피드에서 제외하고, 승인된 범위만 게시합니다. 완료 보고에는 글·퀴즈·카드 링크와 실제 확인 범위·미확인 사항을 남깁니다.

원자료·비공개 과정 안내·개인 대화는 공개 저장소에 넣지 않습니다. 코드잇 과정은 홈페이지의 공식 Discord와 커리큘럼 링크로 접근합니다. 별도 실습 HTML 두 개는 공개 사이트에서 제외했습니다.

이 위키는 [Karpathy의 LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 방식을 참고합니다. 원자료 자동 수집이나 예약 실행은 하지 않습니다. 지도 디자인 참고: [Memory](https://www.careerhackeralex.com/memory). 글꼴 출처는 `vendor/NOTICE.txt`에 있습니다.
