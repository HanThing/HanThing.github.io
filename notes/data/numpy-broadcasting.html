브로드캐스팅 — 어떤 값을 어디에 재사용하는가

2026년 9월 23일9 min read

브로드캐스팅은 shape이 다른 배열의 값을 정해진 위치에서 재사용하는 규칙이다. 수학의 행렬 덧셈 자체가 아니라 반복되는 계산을 배열 문법으로 표현하는 방법이다. 아래 의도는 실제 대화 맥락에서 해석했다. 학습 기록에는 직접 푼 문제의 답도 남겼다.

질문: 수학에 없던 브로드캐스팅을 왜 쓰는가?

상황: 행렬 덧셈은 같은 크기끼리 한다고 배웠는데 다른 shape을 더하는 기능이 등장해 필요성을 물었다.

의도: 규칙을 외우기 전에 해결하려는 문제를 이해하려는 질문이다.

핵심 답변: 모든 학생의 국어에 5점, 영어에 10점을 더하려면 보정값 [5, 10]을 학생마다 재사용하면 된다. 같은 보정 배열을 학생 수만큼 미리 복제할 필요가 없다. 계산은 여전히 각 원소에서 일어난다.

인덱스로 풀면 result[i, j] = scores[i, j] + bonus[j]다. 입력을 복제할 필요가 없다는 뜻이지, 출력 배열의 메모리까지 없어지는 것은 아니다.

질문: (5, 5)에 (5,)를 더하면 어느 5에 맞추는가?

상황: 앞뒤 축 길이가 모두 5라서 어느 방향으로 더하려는지 shape만으로 알 수 없다고 지적했다.

의도: 계산 방향이 수학적으로 필연적인지, 라이브러리의 약속인지 구분하려는 질문이다.

핵심 답변: NumPy는 의도를 추측하지 않고 오른쪽부터 축을 맞춘다. 없는 앞축은 길이 1로 간주한다. 대응하는 길이가 같거나 한쪽이 1이면 계산할 수 있다. 어느 방향을 기본값으로 삼을지는 정해진 규칙이며, 다른 방향은 shape으로 표현한다.

A + b는 A[i,j] + b[j], A + b[:,None]은 A[i,j] + b[i]다. 정사각 배열은 둘 다 실행돼도 의미가 다르다. 오류가 없다는 사실만으로 원하는 방향이라고 판단할 수 없다.

당시 “코드와 숫자를 함께 보니 추상적이라 어렵다”는 말 뒤에 설명이 얕아졌고, 학습자는 이해의 깊이를 제한하지 말라고 요청했다. 이후 설명에서는 규칙인 부분과 그 규칙으로 계산되는 과정을 나누어 다뤘다.

질문: (10, 1)과 (5,)에서도 왜 (10, 5)가 나오는가?

상황: (10, 5) + (5,)와 (10, 1) + (5,)가 같은 결과 shape이라는 점을 질문했다.

의도: 큰 입력 하나에 맞추는 것으로만 이해한 규칙을 확장하려는 질문이다.

핵심 답변: 두 번째 식은 양쪽이 서로 다른 축에서 재사용된다. (10, 1)은 마지막 축에서, (1, 5)로 비교되는 다른 입력은 앞축에서 재사용된다. 결과가 어느 입력보다도 클 수 있다. shape이 같다고 값까지 같다는 뜻은 아니다.

입력 shape결과
(10, 5) + (5,)(10, 5)
(10, 1) + (5,)(10, 5)
(10, 5) + (10,)마지막 축 5와 10이 충돌, 오류
(3, 1, 4) + (2, 4)(3, 2, 4)

확인할 때는 a = np.ones((3, 1, 4)); b = np.ones((2, 4))처럼 배열을 먼저 만든 뒤 (a + b).shape을 읽는다. 별도 브로드캐스팅 함수 호출은 필요 없다.

질문: normal의 평균과 표준편차는 한 묶음 안의 숫자에 적용되는가?

상황: loc=[100, 50, 10], scale=[20, 5, 2], size=(1000, 3)으로 만든 데이터의 분포를 물었다.

의도: 샘플 안의 위치와 축, 모집단의 생성 기준과 실제 표본 통계를 구분하려는 질문이다.

핵심 답변: 각 열은 서로 다른 정규분포에서 생성된다. 첫 위치는 평균 100·표준편차 20인 분포, 두 번째는 50·5, 세 번째는 10·2다. 한 행의 세 숫자를 평균 내서 100, 50, 10을 얻는다는 뜻이 아니다.

scale=20은 값이 평균 ±20 안에서만 나온다는 뜻이 아니다. 42는 재현을 위한 시드다. 같은 환경에서 생성기를 다시 만들고 같은 순서로 호출해야 같은 결과를 비교할 수 있다. 같은 생성기로 한 번 더 호출하면 다음 난수가 나온다.

rng.normal()은 난수 생성, np.linalg.norm()은 길이 계산이다. 실습에서 normal = (X - mean) / std라고 쓴 normal은 학습자가 붙인 변수 이름이며, 앞의 메서드와 별개다.

질문: feature별 평균을 빼고 표준편차로 나누는 것도 브로드캐스팅인가?

상황: 표준화 실습에서 mean의 shape과 X - mean을 물었고, 당시 사용 코드에서는 std 계산이 사용보다 뒤에 있었다.

의도: 통계 공식과 배열의 실제 실행 순서를 연결하려는 질문이다.

핵심 답변: (N, D) 데이터의 feature별 통계는 (D,)이다. j번째 feature의 평균과 표준편차를 모든 샘플에서 공통으로 쓴다. 정의하는 줄이 사용하는 줄보다 앞에 있어야 현재 X의 통계로 계산한다.

표준편차가 0이 아닌 feature에 적용하면 같은 데이터의 평균은 약 0, 표준편차는 약 1이 된다. 상수 feature는 0으로 나누므로 별도 처리가 필요하다. 기본 std는 ddof=0이다. mean은 평균, min은 최솟값이다.

Core 6에서 이어진 흐름은 다음이었다. 아래는 당시 답변의 풀이를 재구성한 것이며 완성·제출 증거는 아니다.

표준화한 첫 feature가 양수라는 것은 원래 값이 그 feature의 평균보다 크다는 뜻이다. 행 선택과 행렬곱은 불리언 마스크, 선형 계층으로 이어진다.

퀴즈: 행마다 자기 평균을 빼려면?

X = np.array([[2., 4., 6.], [10., 20., 30.]])에서 각 행의 평균을 빼려 한다. X - X.mean(axis=1)은 가능한가? 원하는 코드와 결과를 쓰자.

정답과 이유 보기

(2,3)과 (2,)는 오른쪽 축이 충돌한다. X - X.mean(axis=1, keepdims=True)를 쓰면 평균이 (2,1)로 남아 [[-2,0,2],[-10,0,10]]이 된다.
