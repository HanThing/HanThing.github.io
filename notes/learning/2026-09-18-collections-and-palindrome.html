회문 비교와 중복 제거에서 어떤 값을 써야 할까?

2026년 9월 18일6 min read

같은 날 회문 판별과 자료구조 문제를 풀며 나온 질문이다. 문법 이름을 나열하기보다 입력을 어떤 값으로 바꾼 뒤 비교·순회해야 하는지를 확인했다. 아래 결과는 당시 설명의 예이며 수정 후 사용자 실행이 확인된 것은 아니다.

질문 제목은 실제 발언의 뜻을 유지해 다듬었다. 의도는 사용자가 직접 밝힌 경우를 제외하면 대화 맥락을 바탕으로 정리한 해석이다.

질문: 회문 문제의 대소문자를 무시한다는 조건은 어떻게 충족할까?

상황: 앞에서 읽어도 뒤에서 읽어도 같은 문자열인지 판단하는 문제에서 “대소문자를 무시”하는 조건을 보고 힌트를 요청했다.

의도: 완성 정답을 받기보다 비교 전에 해야 할 처리를 찾으려 했다.

핵심 답변: 당시 영문 예에서는 .lower()로 모두 소문자로 바꾼 뒤 비교할 수 있다. .lower()는 원본 문자열을 직접 고치지 않으므로 반환된 문자열을 사용해야 한다.

이 힌트는 해당 문제의 영문 입력 예를 기준으로 한다. 모든 언어의 대소문자 비교 문제를 같은 한 줄로 해결한다고 일반화하지 않는다.

질문: lower를 썼는데 회문 판별 코드가 왜 틀릴까?

상황: 힌트 뒤 사용자는 “뭐가 문제지?”라고 물었다. 당시 코드를 확인한 설명에서는 text.lower()의 결과를 저장하지 않은 점과 text[len(text)-1]로 오른쪽 비교 위치를 고정한 점이 확인됐다.

의도: 첫 힌트를 적용한 코드에서 여전히 조건이 맞지 않는 위치를 찾으려 했다. 구체적인 제목은 당시 확인된 코드 맥락을 복원한 것이며 사용자의 짧은 질문을 그대로 인용한 문장은 아니다.

핵심 답변: 변환 결과를 text에 다시 저장해야 하고, 왼쪽 인덱스 i가 움직이면 오른쪽도 len(text)-1-i로 움직여야 한다. level에서 두 번째 비교는 e와 마지막 l이 아니라 양쪽의 e여야 한다.

당시 답변은 공백 제거 조건도 짚고, 실패를 나타내는 flag 변경은 break보다 앞에 있어야 한다고 안내했다. 사용자가 수정한 뒤 성공했다는 기록은 없으므로 완료로 남기지 않는다.

질문: 중복값을 제거하고 정렬된 리스트로 만들려면?

상황: 사용자는 “중복값 제거 어떻게 하지?”라고 물었다. 당시 설명은 문제에서 요구한 정렬된 리스트까지 연결했다.

의도: 같은 값이 여러 번 나온 입력에서 각 값을 한 번만 남기는 방법을 알고 싶었다.

핵심 답변: set은 중복 원소를 담지 않지만 순서를 보장하지 않는다. 이 문제처럼 정렬된 리스트가 필요하면 sorted(set(numbers))로 중복 제거와 정렬을 이어서 한다.

원래 등장 순서를 보존하라는 조건이라면 다른 요구다. 이 예의 오름차순 정렬과 혼동하지 않는다.

질문: dict.items()는 키와 값을 담은 튜플 하나를 반환할까?

상황: 딕셔너리의 items가 키·값 튜플을 반환하는 함수인지 확인했다. 앞서 두 값을 두 변수에 나누어 받는 언패킹을 배운 상태였다.

의도: 반환 객체 전체와 반복할 때 꺼내는 항목 하나를 구분하려 했다.

핵심 답변: items()는 딕셔너리 뷰를 반환하고, 그것을 순회할 때 각 항목이 (키, 값) 튜플이다. 뷰 자체를 튜플 하나라고 부르면 반복 구조를 놓친다.

첫 항목 ('apple', 3)이 key와 value로 나뉜다. list(data.items())는 그 항목들을 리스트로 모으는 별도 작업이며, items() 자체는 원본 딕셔너리의 변경을 반영하는 뷰다.

관련 개념: 반복 가능한 객체와 이터레이터, break의 범위, 문자열 변환과 언패킹.
