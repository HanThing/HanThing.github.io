정답을 맞혔는데 왜 실패 안내까지 실행될까?

2026년 9월 18일7 min read

9월 18일 Colab의 7번 숫자 맞히기 문제를 풀던 중 나온 질문이다. 당시 답변에 제시된 조건은 1부터 50 사이의 정수를 맞히고 최대 여섯 번 입력하는 것이었다. 정답보다 작으면 up, 크면 down, 맞히면 정답 안내 후 반복을 끝내는 구조였다.

문제는 정답을 맞힌 뒤에도 반복문 밖의 실패 안내로 흐름이 이어진다는 점이었다. 사용자는 반복을 멈추는 break는 알고 있었지만 정답 이후 더 이상 실행하지 않으려면 프로그램 자체를 종료해야 하는지 물었다.

질문 제목은 실제 발언의 뜻을 유지해 다듬었다. 의도는 사용자가 직접 밝힌 경우를 제외하면 대화 맥락을 바탕으로 정리한 해석이다.

질문: 정답을 맞혔으니 break 대신 프로그램 실행을 끝내려면?

상황: 사용자는 “7번 문제 9번 라인 break 대신에, 정답을 했으니까 그냥 이제 실행을 끝내고 싶은 상황”이라고 특정 위치와 원하는 동작을 말했다. 당시 코드를 확인한 답변에서는 마지막 "아쉽습니다..." 출력이 반복문 밖에 있었다고 설명했다.

의도: 사용자가 직접 말한 요구는 정답을 맞힌 뒤 실행을 끝내는 것이었다. 답변은 이를 현재 코드에서 성공 뒤 실패 안내가 나오지 않게 하려는 요구로 해석했다. 프로그램 전체 종료가 반드시 필요한 별도 요구로 확인된 것은 아니다.

핵심 답변: break는 가장 가까운 반복문만 끝내므로 그 다음 문장은 실행된다. 이 문제에서는 정답이면 break하고, 여섯 번 모두 실패한 경우의 안내를 for에 붙은 else로 옮기면 성공·실패 흐름을 구분할 수 있다.

당시 관찰한 코드의 핵심 구조는 아래처럼 설명됐다. 생략 부분이 있는 구조도이며 사용자 원본 전체가 아니다.

경우사용자가 원한 동작위 구조의 흐름
여섯 번 안에 정답정답 안내 후 종료break 뒤 반복문 밖 실패 안내로 이동
여섯 번 모두 오답실패 안내와 정답 표시반복을 마친 뒤 실패 안내로 이동

여기서 오른쪽 열은 당시 확인된 코드 구조의 분석이다. 실제 실행 화면에서 두 문장이 출력된 로그를 따로 확인했다는 뜻은 아니다.

종료 명령보다 실패 안내의 위치가 먼저였다

당시 답변은 일반적인 종료 요청으로 sys.exit()를 먼저 소개했다. 다만 Colab에서는 SystemExit가 처리되면서 셀 실행이 중단될 수 있고, 런타임 자체를 종료하거나 변수 상태를 지우는 것과는 다르다고 설명했다.

이 문제의 요구를 표현하는 데에는 다음 구분이면 충분했다.

마지막 else는 정답 검사 if가 아니라 for와 같은 들여쓰기다. 답변에서는 이 구조로 고친 코드를 제안했으며, 사용자가 실제로 수정·재실행했다는 후속 기록은 없다.

입력 없이 흐름만 확인하는 작은 예

아래는 정리하면서 만든 설명용 재구성이다. 원래의 무작위 정답과 여섯 번 입력 대신 정답 7, 입력 후보 두 개를 사용해 종료 관계만 남겼다.

정리 시 실행 확인한 출력은 정답, 반복문 다음이다. 정답을 찾아도 반복문 뒤의 문장은 실행된다. [3, 5]로 바꾸면 break를 만나지 않아 기회를 모두 사용함, 반복문 다음이 출력된다. 이는 작성한 예제의 검증이며 사용자의 과제 수행 결과가 아니다.

남은 확인

확인된 것은 실제 질문, 당시 코드 위치에 대한 설명, for–else 수정 제안이다. 사용자가 두 경우를 직접 실행하거나 들여쓰기의 이유를 자기 말로 설명한 기록은 아직 없다. 복습 문제는 실제 질문과 분리해 반복문 종료와 for–else에 두었다.

함수 단위 종료인 return과 sys.exit()의 차이도 위 개념 문서에서 비교한다. 노트북 실행을 멈추는 것과 이전 변수 상태를 지우는 것의 차이는 노트북 실행 상태와 연결된다.
